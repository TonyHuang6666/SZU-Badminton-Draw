## 5.0.0（发布说明草案）

5.0.0 重做了赛事工作流：先决定举办团体赛还是单项赛、包含哪些项目，以及本次只做公开抽签还是筹备完整赛事，再进入名单、抽签、统一排程和现场执行。本文是候选 Release 说明，正式发布前仍需完成远端 CI 与真实 Windows 门禁。

> 状态说明（2026-10-03）：赛事助手式 GUI 已完成本地构建、全量回归及 macOS 代表页面原生检查，详见[本轮 GUI 验证报告](../acceptance/v5-gui-2026-10-03.md)。本轮未推送、未运行远端 CI、未完成 Windows 真机验收，也未正式发布。以下“本地候选验证”仍单独保留历史提交 `9c476ab` 的证据，不能扩大为本轮结论。

### 核心变化

- 一个 `.szbd` 工作区承载整场赛事；团体赛与单项赛不能混排，单项赛可包含一至五个项目。
- 新建时显式选择“仅公开抽签”或“完整赛事筹备”。导入名单不自动抽签，抽签也不自动排程。
- 开始公开抽签后保存“抽签结果（待确认）”，确认和导出分别执行，可配合公开线上会议完成抽签并在之后继续办赛。按当前设置重新抽签会实际生成并保存新的待确认结果。
- 单项目使用项目完成节奏；多项目由全赛事策略统一优化，所有项目共享比赛日、场地、裁判容量、休息和每日场次限制。
- 引入无时间比赛关系图、全局赛程板、未决胜负路径约束、容量预检、质量诊断，以及单场/连锁/跨日移动和撤销。
- 现场执行页统一记录表检查与赛果导入、材料包导出、审计历史和健康/损坏存档恢复。
- 赛果更正需要明确确认和原因；重复、冲突、过期、畸形及来源不一致的数据不会静默覆盖工作区。
- 删除 4.x 的旧窗口、旧单项目调度、多存档合并和旧记录路径；Windows 与 macOS 共用 Avalonia 入口。

### 本地 GUI 更新

- 以比赛概览、准备名单、公开抽签、安排赛程、比赛现场、完成与归档六步导航组织任务；赛程板归入安排赛程步骤。
- 首页突出创建和继续比赛；首页、新建流程隐藏先前比赛的标题、导航与路径。最近列表可移除入口，赛事文件不会因此删除。
- 新建向导使用带说明的比赛类型与目标选项；抽签、确认、导出和继续排程分别执行，只做公开抽签时可导出后停止。
- 公开抽签页底统一为“导出抽签结果…”入口，范围、格式和 PDF 分页集中在设置窗口。全部确认的多项目默认全部，否则默认当前；全部项目必须已抽签且确认状态一致才能一起导出，单项目不重复显示全部范围。包含 PDF 时显示可展开的分页设置，选择导出文件夹后按具体文件确认同名替换。
- 待确认结果也可导出，材料标明“抽签结果（待确认）”，文件名带“待确认抽签结果”，不会自动确认。取消设置不导出、不保存存档或改变上次设置；会话、项目或页面变化后旧请求失效。完整筹备赛事全部确认后，以继续安排比赛时间为主要操作；只做公开抽签时以导出为主要操作，进入赛程无须先导出。
- 常用排程设置优先显示；不可用时段、裁判容量、休息、负载、分段时长等在高级设置中保留。折叠不会清空草稿。
- 比赛现场默认先导出材料，再记录比赛结果、查看比赛进展与后续对阵。高级导出选项按需展开，范围确认、诊断、更正前后值和实际操作结果仍保留。
- 备份与恢复区分当前比赛恢复和无法打开的损坏文件恢复；完成与归档显示真实未完成场次，备份不会改变赛事完成状态。
- 统一浅色与深色外观、页面层级与底部操作区。本次改版保留原有数据格式、调度规则、确认和恢复保护。

本轮 Release 构建为 0 警告、0 错误；全量回归 **1,105/1,105** 通过，其中共享层 779、Desktop 326，0 失败、0 跳过。macOS 原生检查覆盖欢迎、新建和代表赛事页面及赛程板，不代表全部尺寸、状态或完整键盘／读屏矩阵已验收。具体证据和未重跑项目见 [GUI 本地验证报告](../acceptance/v5-gui-2026-10-03.md)。

### 不兼容变化

- 5.0 工作区 schema 为 500，不读取或迁移 4.x 存档。
- 不再存在“先分别排项目、再合并多个存档”的操作方式。
- 团体赛和单项赛必须建立为不同赛事；需要查看旧赛事时继续使用对应旧版本。
