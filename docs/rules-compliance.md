# 羽毛球竞赛规则对应关系

本文说明抽签、赛程和赛果工作流与规则设计参考的关系，并明确校园赛事采用的约定、程序检查范围和裁判长职责。具体算法见[算法说明](algorithm.md)，参数与操作见[赛程编排说明](scheduling.md)，公开留档流程见[公平性与公开审计](fairness.md)。

## 参考资料的范围

项目设计参考资料为《羽毛球竞赛规则2025（节选）》。下表的章节编号沿用该节选的引用口径，用于解释设计依据。仓库未附可供逐条复核的完整规则原文，因此这些对应关系应作为项目设计说明阅读，不能据此认定软件通过官方合规认证，或认定该节选是本次赛事应适用的最新规则。

正式使用时，组织方应确定适用的规则版本、赛事规程及补充规定，再核对软件的具体行为与参数。程序中的种子表、默认休息时间、每天最多场次和材料格式各有实现边界，最终解释与现场裁定由组织方和裁判长负责。

| 设计参考主题 | 节选中的对应位置 | 在本项目中的用途 |
| --- | --- | --- |
| 循环赛轮转、奇数轮空、同单位先赛 | 1.2 附近 | 建立组内单循环场次和同单位优先顺序。 |
| 分组循环赛 | 1.4 | 按组数均衡分组，再生成组内对阵。 |
| 非 2 的幂参赛数的轮空 | 2.2 | 逐组安排首轮赛及直接晋级位置。 |
| 单淘汰赛与附加赛 | 2.1、2.4 | 主树产生冠、亚军，另行增加名次赛。 |
| 种子数量与位置 | 2.3.1、2.3.2 | 数量分档校验、种子签位保护。 |
| 同队/同会员协会的分区回避 | 2.3.3 | 以校园报名单位字段实施尽量分散。 |
| 预赛出线与正赛位置 | 2.5.1 | 理解出线结构；具体校园目标由组织方选择。 |

| 抽签后的变更 | “五、抽签变更” | 区分待确认抽签结果与正式确认，变更记录原因并保留审计。 |

## 种子数量与排名

种子数量按参赛方数计算，单打计人、双打计对、团体计队。程序允许的最多种子数如下：

| 参赛方数 | 最多种子数 |
| ---: | ---: |
| 1—15 | 2，且不超过实际参赛方数 |
| 16—31 | 4 |
| 32—63 | 8 |
| 64—128 | 16 |
| 129 及以上 | 32 |

填写的序号必须在允许范围内且互不重复，并与种子标记对应。未编号种子可保留并显示提醒；明确的高低位保护使用种子序号，组织方应在公开抽签前确定完整排序。

程序根据报名数据执行这些设置，不根据历史成绩或选手水平自动决定种子。种子的选拔依据和同批次排序方法应写入赛事规程或领队会记录。

## 种子签位与同单位分散

程序内置的典型保护位置如下，编号从签表顶部的 1 开始：

| 签位规模 | 种子位置顺序 |
| ---: | --- |
| 16 | 1、16、5、12 |
| 32 | 1、32、9、24、5、13、20、28 |
| 64 | 1、64、17、48、9、25、40、56、5、13、21、29、36、44、52、60 |
| 128 | 1、128、33、96、17、49、80、112、9、25、41、57、72、88、104、120 |
| 256 | 前 16 位为 1、256、65、192、33、97、160、224、17、49、81、113、144、176、208、240；完整 32 位表见[算法说明](algorithm.md)。 |

2、4、8 签位分别采用顶部与底部位置；未列入内置表的规模使用递归分区顺序。这些位置体现高位种子分居不同分区的设计参考。

分组阶段还综合小组容量与单位回避：先比较加入某组产生的同单位冲突数，再比较与种子首选组的距离，最后比较当前人数。因此应将最终小组和签位一并核对，不能从种子序号直接推定每次都会进入某个固定编号的小组。

同批次种子的落位采用确定的序号顺序。赛事若要求 3/4 号、5—8 号等在相应保护区再次抽签，应先公开完成相应排序或抽签，并检查输入序号能否准确表达该规程。程序没有独立的同批次二次抽签步骤。

## 轮空与首轮赛

设某组有 `n` 个参赛方，`b` 为不大于 `n` 的最大 2 的幂。程序先安排 `n−b` 场首轮赛，让其胜者和 `2b−n` 个直接晋级者组成 `b` 个正赛入口。

| 小组参赛方数 | 首轮赛场数 | 直接晋级正赛数 |
| ---: | ---: | ---: |
| 3 | 1 | 1 |
| 5 | 1 | 3 |
| 6 | 2 | 2 |
| 7 | 3 | 1 |

对于非 2 的幂人数，直接晋级数等于上一级完整签表的空位数。程序优先为高位种子保留这些位置，并把首轮胜者与直接晋级者接入受保护的主树。轮空本身不形成需排程、计时或填结果的比赛。

材料中的“首轮赛”表示当前小组为进入完整主树而先进行的比赛。正式赛事中的预赛还可能包含候补、资格、正赛位置和发布要求；这些应按该赛事规程另外组织。Excel 中首轮胜者入口与直接晋级入口使用不同填色，实际胜者须经赛果流程确认。

## 小组出线与冠军目标

组数和出线目标共同决定比赛结束位置：

- 单组淘汰赛以决出冠军为目标。
- 多组且组数为 2 的幂时，可选择各组分别出线，或让出线方继续参加跨组冠军段。
- 多组且组数非 2 的幂时，使用各组分别出线的结构。

例如 29 队分 8 组，“每组出线”得到 8 个名额；“决出冠军”继续安排 8 强、4 强和决赛。校园预选也可以使用 5 组、3 组分别产生名额，后续集中赛的报名与规程由组织方安排。

这是一项明确的赛制能力范围。它并不自动确定校区名额比例，也不自动建立“某组只能在某校区比赛、后续统一转场”的调度约束。若赛事有此要求，应在公示赛制与安排资源时分别落实。

## 名次附加赛

单淘汰主树确定冠军和亚军。程序通过以下可选场次区分后续名次：

| 名次赛 | 对阵来源 |
| --- | --- |
| 3/4 名赛 | 冠军段两场半决赛的负者。 |
| 两场 5—8 名半决赛 | 冠军段四场四分之一决赛的负者，按对应分支配对。 |
| 5/6 名赛 | 两场 5—8 名半决赛的胜者。 |
| 7/8 名赛 | 两场 5—8 名半决赛的负者。 |

“只排 3/4 名”增加 1 场，“排 3—8 名”增加 5 场。它们是附加的比赛分支，正赛中的抽签位置保持固定。

适用条件以冠军段入口数为准：单组使用首轮结束后的主树规模，多组冠军赛使用小组数。少于 8 个入口时，“排 3—8 名”按可执行范围降为 3/4 名赛；少于 4 个入口时无名次赛。循环赛和“每组出线”目标不建立这套名次附加赛。组织方应在抽签前确认所需名次是否能由该结构产生。

排程要求名次赛的开始时间不晚于同项目冠军决赛开始时间，允许同时开始。若颁奖安排需要名次赛在决赛之前全部结束，还应人工检查各场结束时间。

## 循环赛与最终名次

循环赛采用轮转法，每对参赛方在组内相遇一次，奇数参赛时自动形成轮空。单项赛中的同单位对阵优先排列；最终日期时间还须满足场地、裁判、个人休息和每日场次等硬条件。

输出矩阵保留胜场、净胜和名次列，并提供场次编号与比赛顺序。单场胜负可进入工作区，循环赛最终名次、并列比较顺序、弃权及特殊成绩处理仍由裁判长按本赛事规程完成。

团体循环赛以队伍为参赛方，使用普通轮转顺序。软件中的一场比赛表示一次队伍对抗；队内三场制、五场制、胜负提前结束条件和具体上场队员不在比赛关系图中。

## 赛程编排的硬条件

一场赛事使用统一资源与全局赛程。共享校验器在生成和调整时检查：

- 比赛在已定义的日期、开放时段和场地内，时长与项目设置一致。
- 场地不重叠，避开已输入的不可用时段，并满足裁判总容量和分时容量。
- 来源比赛先结束，后续场次才开始；已完成和锁定比赛保持位置。
- 单项选手按学号优先的身份规则检查兼项、最小休息和全项目累计每日上限。
- 能够同时成立的未决晋级路径同样满足上述个人约束。
- 名次赛及启用后的冠军决赛末日要求得到满足。

休息与每日上限是组织方明确设置的硬约束。默认 30 分钟和 4 场只代表桌面初始输入；本项目没有据此声称它们适合所有级别、年龄和计分制的赛事。组织方须对照适用规程设置数值，不能通过确认一条提醒跳过当前硬条件。

概率模型帮助阅读可能负荷，不参与放宽硬限制。模型未知或出现概率较低时，只要相容路径仍可能违反约束，就需要调整安排或由组织方明确修订合法的资源参数。

桌面采用尽快完成的紧凑安排。多项目单项赛可选择把冠亚军决赛固定在实际日期最晚的资源日；该项属于组织方的排程要求，不能据此推导半决赛、小组出线战或名次赛也必须在末日。

团体赛桌面按整场队伍对抗的统一时长安排，不应用个人休息和每日场次限制；同队撞场、场地与裁判占用以及晋级依赖仍校验。团体队员的实际负担需要结合阵容及子场安排单独审查。

## 校园单位与场馆信息

名单的“学院/学部”和“搭档学院/学部”用于表达校园报名单位。程序对非空单位去除首尾空白并忽略大小写后比较，名称相同即参与回避。组织方应统一简称和院系层级，明确跨学院双打如何报名。

桌面内置粤海东馆 32 片、丽湖至快 12 片、丽湖至畅 10 片场地，也可输入自定义场馆。清单提供选择和材料标识，实际预约、开放时间与临时禁用仍需组织方核实。

当前模型没有选手个人不可用时间、小组所属校区、集中阶段指定场馆、跨校区交通时间、具体裁判资格或轮换安排。不同馆之间的通行时间须单独考虑，普通最小休息参数无法完整表达转场需求。

## 抽签确认、变更和证据

抽签先保存待确认结果，再由操作人员明确确认。确认后的签表建立固定比赛关系图，正式材料保留随机种子、输入哈希、生成及确认信息。

无赛果时，解除确认须填写原因，相关比赛图、全局赛程及待赛凭据按流程失效；已有赛果后禁止解除抽签确认或整场重新生成。后续可调整未完成比赛的位置，但不能借移动改写对阵关系。

记录表导入依据工作区、项目、比赛及图版本等身份进行校验；重复导入、待赛凭据、胜负冲突及允许的元数据更正有明确处理边界。更正保留原因、前后值和文件/行来源。备份恢复也保存原因和新修订。组织方应把现场裁定与这些记录共同留档。

## 程序职责与赛事职责

| 程序提供 | 组织方或裁判长负责 |
| --- | --- |
| 执行种子数量、序号和保护位置规则 | 确定种子人选、依据及同批次排序办法。 |
| 生成分组、淘汰树、循环赛及可支持的名次赛 | 确定赛制、出线名额、排名规则和参赛资格。 |
| 校验已建模的场地、裁判容量、依赖及个人负荷 | 核实实际预约、人员资格、体能需求、转场与现场延误。 |
| 按队伍对抗安排团体赛 | 安排队内子场、出场名单、重复出场限制与场序。 |
| 导入经过身份和赛果规则检查的记录 | 裁定弃权、争议比分及特殊结果。 |
| 留存确认、调整、更正、导出和恢复审计 | 见证公开过程、公示正式材料并批准赛事执行。 |

有限预算搜索可能未找到可行方案，也不保证最优。程序测试和材料验收检验的是实现行为；正式赛事是否符合适用规程，仍须对照完整规则、补充规定和现场条件判断。相关实现可从 [OfficialDrawRules](../src/BadmintonDraw.Core/OfficialDrawRules.cs)、[MatchTopologyBuilder](../src/BadmintonDraw.Core/MatchTopologyBuilder.cs) 与 [TournamentPlacementValidator](../src/BadmintonDraw.Core/Scheduling/TournamentPlacementValidator.cs) 复核。
