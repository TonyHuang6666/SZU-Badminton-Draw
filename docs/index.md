## 普通用户路线

一场完整赛事的推荐顺序是：

```text
创建赛事文件
  → 导入并检查各项目名单
  → 公开生成、确认并导出抽签结果
  → 统一设置日期、场地和人员容量
  → 生成并调整全赛事赛程
  → 导出现场材料
  → 预览并导入赛果
  → 备份和归档
```

如果本次只负责公开抽签，可以在“确认并导出抽签结果”后安全停止，以后再把同一赛事继续为完整筹备。名单导入不会自动抽签，抽签也不会自动排程或导出现场材料。

## 5.0 的关键边界

- 一个 `.szbd` 文件代表一整场赛事，而不是一个项目。
- 一场赛事只能选择团体赛或单项赛，不能混排。
- 单项赛可包含男单、女单、男双、女双、混双中的一至五项。
- 多项目从一开始共享比赛日、场地、裁判容量、休息和每日场次上限，不再先各自排程后合并。
- 5.0 工作区 schema 为 500，不读取或迁移 4.x 存档。
- 团体赛当前以“队伍之间的一场团体对抗”为调度和总赛果单位，不管理每个子场的具体上场队员和时间。
- 循环赛最终排名、种子人选、退赛替补、现场延误和规程解释仍由赛事组织方负责。

## 文档类型与可信边界

### 当前产品文档

`usage.md`、`scheduling.md`、`fairness.md`、`rules-compliance.md`、`troubleshooting.md`、`architecture.md` 和 `algorithm.md` 描述当前 5.0 代码及其已知边界。行为冲突时以代码、测试和最新验收证据为准，并应修正文档。

### 冻结验收与发布文档

`acceptance/` 和 `releases/` 中的文件记录特定候选提交的事实。除非重新执行并记录验证，否则不要只修改测试数量、产物哈希或平台结论。

### 设计、计划与实施记录

`superpowers/specs/` 和 `superpowers/plans/` 用于记录设计决策、实施计划和过程证据。它们帮助理解为什么这样设计，但不是普通用户的操作手册，也不代表其中所有未来设计已经进入程序。

## 术语速查

| 术语 | 含义 |
| --- | --- |
| 赛事文件 / 工作区 | 扩展名为 `.szbd` 的整场赛事可信状态。当前界面仍使用“工作区”一词。 |
| 项目 | 男单、女单、男双、女双、混双或团体赛项目。 |
| 抽签预览 | 已保存但尚未正式确认的抽签结果。 |
| 确认签表 | 组织方确认后用于建立比赛关系图的正式抽签结果。 |
| 比赛关系图 | 不含日期和场地的比赛、胜者/负者来源及前后依赖。 |
| 全局赛程 | 所有项目共享的一套日期、时间和场地位置。 |
| 记录日 | 某份现场记录表归属的日期，不一定等于原计划日或实际比赛日。 |
| 导出审计 | 程序保存的导出范围、输出文件和哈希记录；存在文件不自动等于整包成功。 |
| 修订 | 工作区每次成功保存后递增的版本，用于阻止陈旧窗口覆盖新状态。 |
