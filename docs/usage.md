# 5.0 使用说明

本文面向 5.0 开发分支；当前验收状态见[开发进度](superpowers/plans/2026-09-13-v5-progress.md)。5.0 不提供 4.x 存档导入或迁移，也不再使用多个项目存档先排后合的流程。

## 1. 新建赛事，先选择工作目标

新建向导依次收集赛事名称、类型和工作目标，项目及赛制，最后核对摘要和 `.szbd` 保存位置。

- 团体赛：只有一个团体项目。
- 单项赛：从男单、女单、男双、女双、混双中选择一至五项，每种项目只能出现一次。
- 仅公开抽签：完成名单、抽签和公示即可停下，不要求输入任何赛程资源。
- 完整赛事筹备：允许以后进入统一排程和现场执行，但仍必须主动完成抽签、确认等步骤。

团体赛与单项赛不能放在同一工作区里同时编排。不要通过把团体名称写成单项项目来绕过此限制。

工作区在抽签前就创建。每个成功命令会自动保存，不存在最后再点击一次“创建赛事存档”的步骤。回到开始页可以打开本地工作区或最近使用的工作区；最近文件列表不是备份。

## 2. 准备名单和种子

在名单页选择项目，生成名单模板后填写并导入 `.xlsx`。按选定项目解释名单，不根据内容偷偷切换成另一种比赛。

模板字段依次为姓名、学号、学院/学部、搭档姓名、搭档学号、搭档学院/学部、是否种子、种子序号、备注。删除模板示例，再填写正式报名数据；团体名单在学院/学部列填写队伍名称。单打一个参赛方是一名选手，双打是一对选手，团体是一个队伍；显示数量分别使用人、对、队。

学号是兼项识别的重要依据。相同学号跨项目应对应同一位选手；同名不同人应填写不同学号，双打两人分别填写。同一项目中同一选手不能重复报名或属于两对搭档。无学号时只能按姓名识别，遇到同名歧义必须先澄清；不要依赖程序猜测。

导入后核对警告、原文件哈希和种子设置。取消种子时同时清空种子序号；保留旧序号会提示冲突，不能以模糊状态保存。种子由组织方确定，程序不评价运动水平。

全部项目名单有效后，才能进入公开抽签。名单导入不会生成抽签、比赛关系图或赛程。

## 3. 公开抽签与公示

适合在线视频会议共享屏幕的流程：

1. 逐项展示已核对名单、种子、赛制和分组数，公开确定随机数种子。
2. 明确点击生成抽签预览。预览会保存，但还不是确认后的正式结果。
3. 检查分组、首轮赛、轮空、出线目标及名次加赛；需要时导出未确认预览供参会者核对。
4. 确认无误后，单独确认此项目抽签，再导出正式抽签材料。
5. 多项目逐项完成。只有全部项目都处于相同的预览或确认状态时，相应的“全部导出”才可用；也可以单独导出一个项目。

导出可以选择 Excel、A4 PDF、PNG、JPEG 或全部格式。PDF 拼页行列须为正整数。默认不覆盖同名文件；改变项目、格式或拼页参数后，需要重新确认覆盖。

编辑框里的新设置不会自动替代已保存预览。若设置已改，请主动重新预览；导出仍以已保存预览为准。程序显示的随机种子、输入哈希、算法版本、生成与确认时间，应随材料一起留档。

团体或单项淘汰赛可以只让每组产生一个出线者；二的幂次分组可选择继续决出总冠军，单组直接决出冠军。名次加赛只在相应冠军赛制下启用。循环赛生成组内全部对阵，最终小组排名仍需裁判长按赛事规程判定。

公开抽签结束后可以直接关闭程序。以后打开同一工作区会保留已确认签表，不需要重新抽签。“仅公开抽签”工作区可明确升级为完整赛事，升级本身也不会排程。

已确认抽签为只读。如果尚无任何赛果，可以填写原因并确认解除某项目的抽签确认；这会作废该项目比赛关系图和整场全局赛程，需要重新检查、确认和排程。已有赛果后不允许用此入口重抽。

## 4. 统一排程

全部抽签确认后，完整赛事才能进入排程设置。设置共同的比赛日、时间段、场地、不可用场地时段、裁判并发容量、最小休息和每日场次上限，再设置项目预计时长及策略。

只有一个项目时，策略表示该项目的完成节奏；多个项目时，它表示全赛事的共同策略。不会为每项各排一份，再让某份赛程覆盖其他项目。

修改日期或策略只编辑草稿，不会即时重排。点击生成后才尝试排程、完整校验并保存；失败会保留之前的合法工作区和赛程，列出未安排场次、约束及建议。已有赛果后不能重新生成整场赛程，只能调整未完成场次。

详细资源填写、硬约束与偏好的区别见[赛程编排说明](scheduling.md)。默认值是产品初始设置，不是正式赛事规则认证。

## 5. 调整赛程板

赛程板以“时间 × 场地”展示整场赛事，可按日期切换、缩放、定位比赛。拖动只用于提出移动目标，不应把悬停反馈当作已经保存。

在移动编辑区选择比赛、目标日期、开始时间和场地，预览本场移动或连锁移动，检查每条原位置和新位置，再确认保存全部变更。连锁移动只自动调整本项目受影响的后续比赛，但必须通过全赛事资源、兼项和休息校验。无法安放整个变更集时，不保存其中一部分。

已完成比赛不能移动。撤销上次移动也是受当前状态校验的保存操作，不是无限历史回退；切换工作区、重新载入、赛果导入等改变状态后，旧预览和旧撤销资格可能失效，需要重新核对。

## 6. 导出现场材料

在现场执行页选择全部项目或一个项目，明确勾选材料日期，选择输出目录。若要将以前记录过但尚无赛果的场次带入某天材料，需另外启用待赛顺延并指定目标日；默认不启用，也不会自动找“下一日”。

核对范围、PDF 拼页和覆盖选项后确认范围，再发起导出。改变来源、范围、目录或拼页设置会撤销原来的确认。空日期范围不是“全部日期”。

材料按实际内容生成：

- 每个选定项目的完整带时间场地对阵 Excel 与 A4 PDF；日期筛选不裁断项目签表。
- 非空项目日期的记录 Excel。
- 非空材料日的赛程 Excel、合并记录 Excel、单项计分 PDF 或团体计分 Excel。
- 全赛事质量 Excel，以及材料包说明和清单。即使只导出一个项目，质量检查仍覆盖整场赛事。

待赛顺延只改变本次材料呈现：记录日是目标日，原计划日期保留，时间和场地显示“待安排”，未知实际比赛日保持空白。它不移动存档内赛程，不补写赛果，也不等于已完成。实际调整仍在赛程板操作。

看清成功或失败详情中的实际范围、跳过项、文件路径、字节数和哈希。默认不覆盖文件。发生部分发布或审计保存失败时，保留暂存目录和已经报告的输出；正在尝试但状态未知的路径不能算已验证成功。不要直接把残缺目录交给工作人员当作完整材料包。

打印前预览：复杂对阵图增加拼页可能切开连接线；宽记录表文字可能较小；团体计分表按整组子场版式分页；质量表可能使用 A3。实际纸张、打印机及系统字体差异需现场检查。

## 7. 填写和导入记录表

保留程序导出的记录表原件，另存一份用于填写。在真实比赛行中填写比分、用时、胜方、赛果类型和实际比赛日；不要填写示例行，不要删改隐藏 ID、签表版本、确认时间、记录日、原计划信息或对阵来源公式。

- 胜方优先使用表内下拉选项，也支持明确的 `A` / `B`，不靠姓名中的“胜者”“负者”等字样猜测。
- 比分方向始终是 A 对 B，例如 `21-10`；多局用 `21-10, 18-21, 21-17`。程序检查可识别格式、方向和局数，不认证所有赛事的计分规程。
- 正常赛果必须有有效比分和正整数分钟用时。弃权赛果使用明确类型、胜方与零分钟；不要把缺失比分的正常比赛冒充弃权。
- 待赛行的实际比赛日可留空表示未知；有胜方的赛果必须明确填写实际比赛日，弃权也不例外，日期必须已在工作区资源中配置。它与原计划日、材料记录日是不同字段。
- 不填胜方的合法空白行表示待赛；错误格式、冲突身份或有问题的填写不会自动当作安全待赛跳过。

可以一次选择多份、多个日期的记录表。先预览，逐项核对文件哈希、工作表、行号、记录日、诊断、增加/重复/待赛/更正计数；勾选确认后才导入。选择文件、清空列表或修改确认条件不会自动提交。

同一文件内容重复导入不会重复写入赛果。已导入的合法待赛文件可能只有覆盖凭据、没有新增赛果，因此“已覆盖的记录行”和“已完成比赛数”不是同一个数。历史区域同时保留有效和已作废凭据，不能把作废历史当当前待赛来源。

胜负方不同属于阻断冲突，不允许用普通更正覆盖。比分、时长、类型或实际日期等允许的元数据更正，须启用更正、填写原因并重新预览确认；更正前后值及来源会留在历史中。旧文件重导不会反转已经发生的更正。

导入成功后，下游对阵按存档赛果解析。它不会在后台自动导出新材料；核对后再独立选择材料范围。全部真实比赛均有有效赛果后，工作区才成为“已完成”；导出文件或导入待赛表不会使赛事完成。

## 8. 备份、恢复和错误处理

备份入口属于整个程序，不要求先进入现场执行。正常工作区可以主动创建手动备份；记录提示中的已验证副本路径、赛事 ID、修订和哈希。自动备份与手动副本各有用途，创建出一个文件不代表它已经通过完整性检查或对应审计已保存。

恢复正常工作区时选择同一赛事的备份，先预览，再填写原因并确认。恢复会保留目标原状态副本并写入恢复审计，修订继续向前，不能把旧预览带到恢复后的状态继续提交。

无法打开损坏工作区时，仍可进入备份与恢复，明确选择损坏目标及备份。此时程序无法从损坏文件证明原赛事身份，必须人工核对路径和备份摘要。预览后任一来源字节变化，都需要重新检查。

如果提示“已保存但无法重读”，不要把它当成未保存并反复重试；重新载入工作区，核对持久化状态后继续。未提交、候选文件、未验证副本、已提交但重读失败会分别报告，不保证每个失败留下的文件都是可恢复备份。
