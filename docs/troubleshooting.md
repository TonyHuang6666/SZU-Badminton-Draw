# 5.0 故障处理

本页按“先保护赛事数据，再恢复工作”的原则整理常见问题。遇到错误时先记录当前赛事文件、提示文本、候选/备份/暂存路径和操作时间，不要反复覆盖或清理现场。

## 快速判断

| 现象 | 先做什么 | 不要做什么 |
| --- | --- | --- |
| 找不到最近赛事 | 使用“打开工作区”重新选择真实 `.szbd` 文件 | 不要把最近列表当备份 |
| 无法打开赛事文件 | 保留原文件，进入“备份与恢复”检查可用备份 | 不要用空文件或别的赛事覆盖原文件 |
| 提示修订冲突 | 重新载入，核对另一窗口或进程已经保存的内容 | 不要强制覆盖较新的修订 |
| 提示已保存但无法重读 | 重新载入并核对真实持久化状态 | 不要按“未保存”连续重试 |
| 排程失败 | 阅读未安排场次、容量证据和建议，调整明确资源 | 不要把搜索失败直接说成数学无解 |
| 材料导出部分失败 | 按提示区分已验证文件、未知目标和暂存目录 | 不要把残缺目录交付为完整材料包 |
| 记录表导入冲突 | 保留文件，检查工作区、项目、胜方和版本诊断 | 不要删除隐藏 ID 或直接覆盖赛果 |
| 恢复预览失效 | 重新选择目标与备份，再做一次预览 | 不要提交基于旧字节或旧修订的确认 |

## 最近赛事打不开

“最近赛事”只是路径历史，不保存另一个副本。文件被移动、重命名、删除或外置磁盘未挂载时，该入口会失效。

1. 点击“打开工作区”，在磁盘上重新选择 `.szbd`。
2. 如果文件确实被移动，成功打开后最近列表会记录新位置。
3. 如果文件已经丢失，检查原目录旁的 `Backups` 或组织方保存的手动备份。
4. 如果路径存在但无法读取，按下一节处理，不要删除原件。

当前界面可能在底部显示 SQLite 英文技术错误；它说明底层读取失败，不表示系统已经修改了该文件。

## 工作区损坏或无法读取

即使当前没有可读赛事会话，也可以打开“备份与恢复”。损坏恢复时，程序无法从目标文件证明赛事身份，需要人工核对：

- 损坏目标的完整路径和修改时间；
- 备份摘要中的赛事名称、赛事 ID、修订和哈希；
- 备份是否来自同一场赛事；
- 恢复预览之后目标或来源是否又被修改。

恢复会保留目标前像并写入恢复审计。预览后任何来源字节变化都会使确认失效，这是数据保护，不应绕过。

## 保存失败与“已保存但无法重读”

工作区保存经过候选副本、事务校验、备份和替换。错误信息中的状态很重要：

- **未提交**：正式工作区没有被候选替换；保留候选和错误证据供检查。
- **备份或副本未验证**：文件可能存在，但不能据此宣称可恢复。
- **已提交但无法重读**：正式文件可能已经包含新状态；先重新载入核对，不要重复执行同一命令。
- **审计保存失败**：业务文件或导出文件可能已经产生，但审计未完整提交；按提示核对实际输出。

如果程序报告候选、备份或前像路径，先复制提示文本并保留文件。除非已确认恢复完成，不要手工删除。

## 排程没有生成

排程失败不会保存部分结果。按证据类型处理：

1. **输入无效**：修正日期、开始/结束时间、场地、不可用时段、裁判容量、预计时长或项目状态。
2. **已证明容量矛盾**：按诊断增加比赛日或调整组织方明确的每日上限；如果矛盾来自总场次容量，只增加球场未必有效。
3. **本次搜索未找到**：可以增加时间/场地资源、减少不必要软偏好或复核比赛时长，但不能宣称绝对无解。
4. **存储失败**：内存中找到方案不等于已经保存，先按保存状态处理。

不要为让赛程生成而偷偷降低最小休息或每日场次上限；这些属于赛事规程决定。

## 赛程移动或撤销失败

- 拖动和编辑首先生成预览，不等于已经保存。
- 连锁移动只有全部变化都通过全赛事校验才可提交。
- 已完成比赛不能移动。
- 导入赛果、恢复备份、重新载入或切换赛事后，旧移动预览和旧撤销资格会失效。
- 撤销只针对当前允许撤销的一次移动，不是无限历史回退。

重新载入后先核对当前赛程，再重新创建预览。不要根据旧截图或旧提示强行复现位置。

## 材料包不完整或不能覆盖

导出范围、项目、日期、输出目录、拼页或来源状态变化后，原确认会失效，需要重新核对。空日期范围不是“全部日期”。

默认不覆盖同名文件。确需覆盖时：

1. 核对输出目录不是上一场赛事的正式交付目录；
2. 核对项目、日期和来源摘要；
3. 重新勾选覆盖和范围确认；
4. 导出后检查结果中的实际文件、跳过项、哈希和审计状态。

材料文件逐项发布，不能与 SQLite 审计组成原子事务。看见若干文件不代表整包成功；只有结果和已保存审计都确认完整，才可交付。

## 记录表导入被拒绝

常见阻断原因：

- 文件来自另一赛事、另一项目或旧签表版本；
- 隐藏比赛 ID、确认时间或来源信息被删除；
- 胜方与已有结果相反；
- 比分、用时、赛果类型或实际日期互相矛盾；
- 有胜方但未填写已配置的实际比赛日；
- Excel 单元格包含错误公式缓存或无法解释的字面量；
- 选择文件后工作区修订发生变化，旧预览失效。

先使用预览查看文件、工作表和行号诊断。胜方冲突不能通过普通更正覆盖；比分、时长、类型或实际日期等允许更正时，必须启用更正、填写原因并重新预览确认。

内容完全相同的文件重复导入不会重复写赛果。合法待赛记录可能只增加覆盖凭据，不会增加“已完成比赛数”。

## 版本不兼容

5.0 使用 SQLite schema 500，不读取或迁移 4.x 存档。看到版本不兼容提示时：

- 用创建该文件的旧版本打开旧赛事；
- 需要试用 5.0 时，从原始名单新建赛事；
- 不要修改 SQLite `user_version`，这不会把旧结构变成新结构；
- 不要用 5.0 新文件覆盖唯一的旧赛事存档。

## 提交问题时应保留的信息

- 程序版本和来源提交；
- 操作系统、架构和显示缩放；
- 不含隐私的最小复现步骤；
- 完整错误文本和技术详情；
- 工作区修订、候选/备份/暂存路径；
- 输入文件与输出文件的 SHA-256（如可提供）；
- 是否能在副本上复现；
- 涉及打印时的办公软件、字体、纸张和打印机信息。

赛事文件和报名表可能包含个人信息。提交公开 Issue 前应先制作脱敏副本，不要上传真实姓名、学号或联系方式。
