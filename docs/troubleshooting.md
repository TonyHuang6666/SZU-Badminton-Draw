# 故障处理

遇到问题时，先保留原始赛事文件、输入表格和错误详情。底部“操作详情与赛事文件”、现场页面的“本次操作的实际结果”和恢复面板会给出保存状态及相关路径。先据这些信息判断结果，再继续操作。

## 快速判断

| 现象 | 处理入口 |
| --- | --- |
| 最近比赛找不到文件 | 首页“打开已有比赛”，重新选择真实 `.szbd` 路径。 |
| 名单导入失败或种子不合法 | 检查 Excel 格式、列名、项目、选手身份和种子数量。 |
| 卡在“先处理种子编辑” | 到对应项目保存或取消编辑，再离开名单页。 |
| 抽签确认或全部导出不可用 | 检查是否仍有项目未抽签、待确认，或当前设置尚未应用。 |
| “检查并生成赛程”失败 | 阅读输入、容量、未安排场次和约束诊断。 |
| 赛程移动或撤销失败 | 核对锁定状态和冲突，重新载入位置并预览。 |
| 现场材料缺文件或不能覆盖 | 检查所选项目、日期、替换清单和实际发布结果。 |
| 记录表导入被拒绝 | 按文件、工作表、行号和字段修正，重新检查。 |
| 提示修订冲突 | “更多 → 重新读取赛事文件”，核对最新内容。 |
| 提示已保存但无法重读 | 重新读取并检查持久化结果，再决定是否重试。 |
| 文件损坏或恢复预览失效 | 使用“备份与恢复”，核对目标和备份后重新检查。 |

## 最近赛事打不开

最近比赛条目记录文件路径和最近打开／保存信息，并用文件名显示比赛名称。文件移动、重命名、磁盘未挂载或已删除时，该入口可能失效。

1. 确认磁盘或共享位置可访问。
2. 点击“打开已有比赛”，重新选择赛事文件；成功打开后会记录新路径。
3. 如果原文件已经丢失，查找组织方留存的手动备份，以及赛事文件同目录中以 `.backup.szbd` 结尾的自动副本。
4. 如果文件存在但读不出来，保留原件，按“工作区损坏或无法读取”处理。

最近条目上的“×”只移除入口。最近列表中的时间是打开或保存记录；备份是否可用应以恢复检查结果为准。

## 名单导入失败

名单应为有效且未加密的 `.xlsx`，程序读取第一个工作表，并把第一个有内容的行作为表头。可先用“导出名单模板…”重新取得标准表格，再把报名数据复制到相应列。

| 提示或现象 | 核对方法 |
| --- | --- |
| 无法读取名单 | 在 Excel 或 LibreOffice 中打开，确认文件有效、未加密，再保存为 `.xlsx`。 |
| 缺少姓名或搭档 | 确认当前选择的项目；单打填写姓名，双打填写双方姓名，团体填写学院/学部中的队名。 |
| 种子过多、编号重复或超限 | 对照[种子数量表](usage.md#设置种子)，检查全部报名行和种子序号。 |
| “是否种子”为否但有序号 | 按组织方名单把两列改为一致；取消种子时同时清空编号。 |
| 同一选手重复报名 | 检查学号、姓名及双打搭档，确保同一项目内该选手只占一个参赛身份。 |
| 同名、学号缺失或名字不一致 | 对照报名原件逐人核实；不同人使用不同学号，同一人跨项目保持一致。 |

名单页可修改种子；姓名、学号、搭档错误需要修改原表后替换名单。已确认抽签的项目须先在“抽签记录与更正”中解除确认，随后重新检查、抽签和排程。已有赛果时该入口锁定。

### 无法离开种子编辑

“先处理种子编辑”表示一个或多个项目仍处于编辑状态。点击后会定位项目，选择“保存种子设置”或“取消编辑”。即使尚未改值，也须结束编辑。

保存失败时，输入会保留，先修正提示的问题。若出现编辑冲突，“重新载入名单后编辑”会放弃当前种子草稿，载入赛事中最新名单继续编辑；也可取消编辑。

## 抽签按钮或导出范围不可用

“开始公开抽签”需要有效名单和合法设置。分组数、淘汰赛目标与名次加赛须相容；可先把组数与目标逐项核对。

修改设置后，当前显示的抽签结果仍采用其已保存设置。点击“按当前设置重新抽签”生成新结果，或“放弃未保存的修改”恢复原结果所用设置，再确认。

“全部项目”导出要求全部项目均已有抽签结果，而且确认状态一致。已确认和待确认项目混合时，先导出当前项目，或逐项完成确认。“继续安排比赛时间”要求全部项目已确认，可用“还有 N 项未确认 · 查看”定位未完成项目。

抽签导出格式选 PDF 或全部格式时，拼页行数、列数均须为正整数。选择目录期间切换项目、赛事或离开页面后，重新点击“导出抽签结果…”发起本次操作。

## 排程没有生成

先检查比赛日期是否重复，时间是否有效，每天是否选择场地，不可用和裁判时段是否处于当天开放范围内，以及项目时长是否为正整数。

排程失败的证据和处置如下：

| 结果 | 处理 |
| --- | --- |
| 输入无效 | 修正诊断指出的具体字段。 |
| 已证明容量不足 | 按容量类型增加比赛日、开放时间、场地或裁判。若是选手每日上限导致，增加球场通常无法解决。 |
| 本次搜索未找到 | 查看未安排场次和拒绝原因，调整真实资源后重新生成；仍可能存在本次搜索未找到的排法。 |
| 验证未完成 | 该候选方案尚未完成全部检查，继续使用之前已保存的赛程。 |
| 存储失败 | 按下一节的保存状态核对正式文件和保留副本。 |

启用“将各项目决赛安排在最后一个比赛日”时，还要检查最晚日期的容量及决赛前序、休息条件。休息、每日上限和决赛要求属于组织方决定的参数，修改后应重新核对规程。

生成失败会保留原赛程。页面容量估算、未发现容量矛盾和完整排程成功各有不同含义，详细说明见[赛程编排说明](scheduling.md#求解失败不等于数学上无解)。

若输入草稿提示与当前赛事冲突，点击“放弃未保存的修改”并确认，恢复已保存设置后重新填写。已有赛果时整场重新生成入口锁定，使用赛程板调整未完成比赛。

## 赛程移动或撤销失败

已完成比赛的时间和场地锁定。未完成比赛移动时，同样检查前后依赖、场地、裁判、选手重叠、休息、每日场次及已保存的决赛日期要求。

使用“定位本场”“定位关联比赛”查明冲突。需要同时后移后续比赛时，查看连锁方案；全部变更均通过校验后才能保存。拖动悬停反馈用于提示，松开后的最终校验和保存结果才决定是否生效。

导入赛果、恢复、重新读取、切换赛事或其他修改后，预览可能失效。点击“载入最新位置”，重新填写目标并查看方案。“撤销移动”只针对当前允许撤销的一次手动操作，且须满足当前赛事状态。

## 选手兼项信息不符合预期

“选手兼项”至少在两个项目已导入名单后显示，全部项目名单就绪后可打开。只有一个项目时无需跨项目汇总。

查不到应有的兼项选手时，检查该人在各项目是否使用同一学号；某处缺失学号会影响身份匹配。同名多人被合并时，补全各自学号。双打两名选手分别识别，请同时核对搭档字段。

没有赛程时只显示报名信息；“后续可能参加”单列潜在晋级场次，确定场次数和最短间隔仅统计已确定比赛。没有同日可比较场次时，最短间隔显示暂无。身份和统计口径见[选手兼项与负荷核对](scheduling.md#选手兼项与负荷核对)。

## 材料包不完整或不能覆盖

先核对勾选的日期和项目范围。至少选择一个日期；无比赛的日期会跳过每日材料并记录原因，带时间对阵图按完整项目生成。单项目材料使用项目名，多项目每日材料使用“合并”，文件清单见[使用说明](usage.md#先导出现场材料)。

替换已有文件按以下流程处理：

1. 核对项目、日期和 PDF 分页，勾选范围确认。
2. 点击“生成现场比赛材料…”，在系统窗口选择上级文件夹。
3. 出现同名文件清单时，检查每个路径，再点击“替换这些文件”；取消会保留原文件。
4. 导出后检查实际材料目录、文件列表、跳过项及审计状态。

确认只针对本次列出的文件。检查后新出现的同名目标会阻止相应文件发布。名单来源、赛事文件、备份、符号链接和目录受到保护；目标被占用或无写入权限时，关闭占用文件的程序或选择其他可写目录。

材料逐个发布。若中途失败，技术详情会区分已验证发布的文件、尝试发布但状态未知的路径，以及保留的暂存目录。先保留这些证据，核对完整性后再重新导出；交付时使用本次确认完整的材料包。

若所有文件已生成但“审计保存失败”，文件发布与赛事内部记录可能处于不同状态。重新读取赛事文件并核对操作详情，保留已有输出，避免仅凭目录内文件数量判断整次成功。

## 记录表导入被拒绝

在“记录比赛结果”点击“检查记录表”，按诊断中的文件、工作表、行号和字段定位。常见问题：

| 诊断 | 修正方法 |
| --- | --- |
| 文件来自其他赛事或签表版本不符 | 打开对应赛事，或从当前赛事重新导出记录表。 |
| 缺少工作表、隐藏 ID 或确认信息 | 使用完整导出表重新填写，保留“对阵记录表”工作表和 N–T 隐藏列。 |
| 胜方选项无效 | 使用真实参赛方的完整下拉选项，或 `A` / `B`。 |
| 上游赛果缺失 | 同时选择依赖的前置记录表，或先导入前置赛果。 |
| 比分与胜方矛盾 | 按 A–B 方向核对比分与胜方。 |
| 正常赛果缺少有效用时 | 填正整数分钟，例如 `18`、`18m`、`18分钟`。 |
| 弃权类型或用时不符 | 明确选择“弃权”，填写胜方、`0` 分钟和实际日期。 |
| 有胜方但无实际日期 | 在 V 列填写已配置比赛日，推荐 `yyyy-MM-dd` 或有效 Excel 日期。 |
| 同批文件同一场比赛不一致 | 对照原始记录统一胜方、比分、时长、类型和实际日期。 |
| 公式缺少缓存或缓存错误 | 在 Excel 或 LibreOffice 中打开、完成重算并保存，再重新选择和检查。 |

比赛结果的编辑列是比分、用时、胜方、结果类型和实际比赛日期。身份列必须保留可读取的原始值。程序读取已保存的 Excel 内容，检查后再次编辑文件也会使原预览失效。

胜负方与已有赛果相反时，普通更正不会接受。比分、时长、类型或实际日期等元数据更正可在胜负双方保持一致时使用：核对前后值、勾选允许更正、填写原因，再重新检查并确认。

已导入的相同文件内容会跳过，作废文件的覆盖范围保持作废；需要新记录时重新导出。合法待赛行可以留下导入凭据，比赛仍保持待赛，因此导入行数与完成场数分别统计。

## 记录表没有联动或待赛场次没有补入

本表同时包含前置比赛时，前置胜方会通过公式更新后续的胜者／负者。前置比赛在其他文件中且尚无已导入赛果时，记录表显示来源占位；先导入前置赛果，再导出更新后的材料。

补入待赛场次需满足三个条件：存在有效的历史待赛导入记录、当前仍无赛果、记录及原计划早于所选目标日。在“高级导出设置”中勾选“将此前未录入赛果的比赛补入本次材料”，并选择本次已勾选的目标日期。作废凭据不作为依据。

补入只影响材料收录。跨日待赛行的时间和场地为“待安排”，实际赛程改期需到赛程板操作。详细字段说明见[填写和导入记录表](usage.md#填写和导入记录表)。

## 保存失败与“已保存但无法重读”

赛事保存包含候选副本、校验、备份和正式文件替换。查看提示中的提交状态：

| 状态 | 下一步 |
| --- | --- |
| 未提交／工作区未替换 | 原正式文件保留；记录错误，保留候选文件，处理权限、占用等原因后再试。 |
| 备份或副本完整性未验证 | 保留文件，通过“检查备份与恢复范围”验证后再用于恢复。 |
| 已提交但无法重读 | 正式文件可能已包含新状态；使用“更多 → 重新读取赛事文件”，先核对结果。 |
| 修订冲突 | 重新读取，核对其他窗口或进程保存的内容，重新创建操作预览。 |
| 审计保存失败 | 同时检查业务状态、文件输出和赛事记录，按实际结果处理。 |

“已保存但无法重读”时，页面显示的可能是最后一次已知内容。避免连续重复执行导入、恢复或导出；先读取正式文件确认。候选、备份和原状态副本路径应随错误详情留存。

## 工作区损坏或无法读取

先保留原文件，再进入顶部“备份与恢复”。当前没有可读赛事时也可打开此面板。

1. 勾选“赛事文件已经损坏、无法打开”，点击“选择损坏文件”明确目标。
2. 点击“选择备份”，选择独立副本。
3. 点击“检查备份与恢复范围”，核对目标路径、备份赛事名称、身份、保存进度和哈希。
4. 确认备份来自这场比赛，填写原因并勾选确认。
5. 点击“确认恢复并保存”，核对实际恢复结果。

损坏目标可能无法证明其赛事身份，需要人工核对路径和备份摘要。恢复会保留目标原状态副本并写入审计；提示中的保留路径应一并保存。

目标可正常打开时，直接打开该比赛并选备份恢复即可，程序会校验同一赛事身份。恢复检查后，目标或备份字节变化、来源切换、重新读取或关闭面板会使原确认失效。重新检查当前文件再提交。

## 版本不兼容

当前赛事文件采用 SQLite schema 500。版本检查失败时，先确认文件来源和创建它的程序版本，使用与该格式兼容的程序打开，并保留原件。需要建立当前格式赛事时，使用原始报名表新建比赛。

手动修改数据库版本号不能补齐所需表结构、比赛身份和操作记录。使用完整、通过检查的赛事文件或备份恢复。

## 打印文字过小或页面不合适

淘汰赛对阵图可增加 PDF 纵向和横向页数，检查拼接边缘的连接线。每日记录表默认打印 A–M，U–V 的结果类型和实际日期在电子表格中填写。赛程网格行高按文字排版，比赛时长以起止时间为准。

打开实际导出的 PDF 和 Excel 做打印预览，检查纸张大小、方向、缩放、重复表头及中文字体。多项目检查报告部分表采用 A3；团体计分表按整组子场分页。需要报告打印问题时，保留出问题的页码和导出设置。

## 提交问题时应保留的信息

- 程序版本、下载来源或源码提交。
- 操作系统、架构和显示缩放。
- 最小复现步骤和完整错误文本。
- 赛事文件路径、修订，以及提示的候选／备份／暂存路径。
- 输入文件、输出文件和 SHA-256，如可提供。
- 是否能在副本上复现，以及操作前后的保存状态。
- 涉及表格或打印时的办公软件、字体、纸张、打印机和具体页码。

赛事文件和报名表可能包含姓名、学号等个人信息。公开报告问题时请使用脱敏副本，并保留便于本地核对的原始证据。
