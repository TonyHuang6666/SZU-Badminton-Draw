# 5.0 系统架构

5.0 使用一个统一赛事文件承载整场比赛，把“抽签结构”“时间场地位置”和“现场赛果”分开管理。本文面向维护者说明模块边界和主要数据流；算法细节见[算法与工作区模型](algorithm.md)，构建命令见[构建说明](build.md)。

## 解决方案结构

| 项目 | 职责 | 不应承担的职责 |
| --- | --- | --- |
| `BadmintonDraw.Core` | 领域模型、抽签、比赛关系图、全局调度、硬约束、质量分析 | 文件选择器、SQLite、具体 Excel/PDF 写入 |
| `BadmintonDraw.Persistence` | schema 500 的 SQLite 存储、完整性校验、候选副本、备份与恢复 | 赛事业务流程和桌面交互 |
| `BadmintonDraw.Excel` | 名单/记录表读取、Excel/PDF/图片材料生成及版式 | 决定何时确认抽签或提交赛果 |
| `BadmintonDraw.Workflows` | 唯一应用用例入口，协调校验、存储、导入、导出和审计 | 直接绘制界面或绕过领域校验 |
| `BadmintonDraw.Desktop` | Avalonia 窗口、页面、ViewModel、文件选择和用户反馈 | 直接写 SQLite 或复制一套业务规则 |
| `BadmintonDraw.Tests` | 核心、存储、工作流、Excel 和故障测试 | 替代真实桌面及打印验收 |
| `BadmintonDraw.Desktop.Tests` | Avalonia Headless、导航、绑定和异步生命周期测试 | 证明 Windows/macOS 原生交互完全相同 |
| `BadmintonDraw.Acceptance` | 真实工作流的有界端到端运行及证据清单 | 代替人工视觉、Office 和真机验收 |

SQLite 生产依赖只由 `BadmintonDraw.Persistence` 直接持有。桌面和 Excel 工程不应通过新增包引用绕过存储边界。

## 核心数据分层

```text
TournamentWorkspace
├── TournamentProject[]
│   ├── 名单与种子
│   ├── 抽签结果（待确认 / 已确认）及确认审计
│   └── MatchGraph（无时间比赛关系图）
├── TournamentResources（全赛事日期、场地、人员容量）
├── TournamentSchedule（MatchKey → MatchPlacement）
├── MatchResult[]（现场赛果）
├── 导入凭据 / 更正历史 / 导出审计
└── 修订、备份与恢复审计
```

关键分离：

- `MatchGraph` 只回答“谁可能与谁比赛、先后依赖是什么”；
- `TournamentSchedule` 只回答“比赛安排在哪天、几点、哪个场地”；
- `MatchResult` 只回答“实际胜负、比分、用时和比赛日”；
- Excel 显示文字和公式不是数据库身份来源，身份使用工作区、项目、比赛和图版本标识。

## 应用数据流

### 名单到确认签表

```text
名单 XLSX
  → 捕获文件字节与 SHA-256
  → 按项目类型解析并校验身份
  → 保存名单
  → 使用公开随机种子执行抽签并保存待确认的抽签结果
  → 导出待确认的抽签结果（可选，不自动确认）
  → 人工确认
  → 保存确认签表和 MatchGraph
```

导入名单不会隐式执行后续步骤。开始公开抽签、按当前设置重新抽签、确认和导出分别由用户发起；前两者实际生成并保存抽签结果。`DrawExportContext.Status` 对外使用“抽签结果（待确认）”和“抽签结果（已确认）”；待确认导出文件名包含“待确认抽签结果”，已确认文件名保留“已确认抽签结果”。内部 `Preview` API、枚举、审计动作名和 schema 保持不变。

### 比赛图到全局赛程

```text
全部已确认 MatchGraph
  + 一份 TournamentResources
  + 一份全赛事策略
  + 当前赛果和锁定位置
  → 容量预检查
  → TournamentScheduler 搜索
  → TournamentPlacementValidator 完整复验
  → 成功后一次保存完整 TournamentSchedule
```

失败只返回诊断，不保存半份赛程。单项目是项目数量为 1 的统一赛事，不走另一套调度器。

### 现场记录到后续对阵

```text
程序导出的记录表
  → 一次捕获文件字节和哈希
  → 解析原始单元格及诊断
  → 核对工作区 / 项目 / 比赛 / 图版本
  → 按前后依赖检查整批记录与拟变更
  → 人工确认冲突或允许的更正
  → 一次保存赛果、凭据和审计
  → 后续对阵按已保存赛果解析
```

导入不会自动导出下一批材料，也不会把实际比赛日反写为计划位置。

## 保存协议

典型命令采用以下边界：

1. 捕获当前工作区与修订；
2. 在内存生成候选状态并完整校验；
3. 把候选状态写入候选 SQLite 副本；
4. 在候选副本执行事务、schema 和完整性检查；
5. 保存原目标的备份或前像；
6. 替换正式目标；
7. 重新读取并发布新会话。

因此“保存前失败”“已替换但重读失败”和“备份/审计失败”是不同状态。界面和日志不得把它们都简化成同一个“保存失败”。

材料包的多个文件与工作区审计无法构成跨文件事务。导出会先在暂存区生成和校验，再逐项发布，最后保存审计；错误结果必须列出已验证输出、状态未知路径和保留的暂存目录。

桌面抽签材料与现场材料在导出前调用只读冲突检查，复用实际导出规划，按项目、日期和格式列出已有的确切目标文件。无冲突直接导出；有冲突则弹窗逐次确认。桌面请求总是带非空值的 `ConfirmedOverwritePaths`（无冲突时为空集合），只允许替换本次明确接受的路径；后续新出现的冲突不能沿用许可。底层保留 `OverwriteExisting` 给已有显式调用者，只有未提供路径集合时才使用该布尔值。预检查不写审计、候选文件或暂存文件；页面以会话和输入代次拒绝迟到的检查／确认结果，实际发布仍复查受保护路径和同名冲突。这不是跨文件原子事务，也不承诺对恶意并发替换目录或已确认文件提供文件身份锁定。

## 并发与陈旧状态

- 每个工作区保存 `Revision`；命令提交前校验预期修订。
- 两个窗口同时打开同一文件时，旧窗口不能覆盖新修订。
- 抽签确认、导出请求与确认、赛程调整方案、记录表检查结果和备份检查结果均绑定来源会话。
- 重新载入、切换赛事、导入赛果、恢复备份或其他保存成功后，旧检查结果、调整方案和旧确认必须失效。
- 异步操作返回时还要核对当前会话，迟到结果不能污染另一赛事。

## 可扩展边界

新增能力时优先沿现有分层扩展：

- 新的业务约束放入 Core，并由同一校验器覆盖生成与编辑；
- 新的持久化字段通过 Persistence schema 和真实重开测试加入；
- 新的导出格式由 Excel/渲染层实现，但由 Workflows 决定范围和审计；
- Desktop 只负责呈现状态和收集明确确认；
- 任何可改变可信状态的操作都应有工作流命令、修订校验、故障测试和重开验证。

5.0 不背负 4.x 存档兼容。不要为旧格式在桌面层加入“猜测式读取”；旧赛事继续使用对应旧版本。

## 赛事助手呈现层

2026-10-03 的本地实现按“比赛概览、准备名单、公开抽签、安排赛程、比赛现场、完成与归档”组织六步导航。赛程板仍是独立路由，但属于安排赛程步骤；`Archive` 仅汇总真实进度并提供材料与备份入口，不自行推进赛事状态。仅公开抽签的赛事确认结果后也可以进入归档页。

`AppShellViewModel.Presentation` 负责通俗状态、当前步骤、下一步和明暗主题；原始错误、候选文件与备份路径保留在可展开的详情中。首页和新建向导隐藏旧会话的标题、路径及报错，不丢弃尚可重新打开的会话数据。共享样式位于 `Styles/AssistantStyles.axaml`。

公开抽签页底只有“导出抽签结果…”一个入口，`DrawExportOptionsDialog` 集中选择范围、格式及 PDF 分页。当前项目显示项目名，多项目的全部范围显示项目数；单项目不重复提供全部范围。全部确认的多项目默认全部，否则默认当前；全部范围只在每个项目都已抽签且确认状态一致时可选。包含 PDF 的格式才显示可展开的分页设置。设置通过“选择导出文件夹…”交接给文件夹选择器和精确冲突确认；取消设置不导出、不保存存档，也不改变上次接受的设置。

设置窗口、文件夹选择和覆盖确认均捕获来源会话、项目和页面；期间会话、项目或导航变化后，旧请求不能继续使用。完整筹备赛事全部确认后，页底以继续安排比赛时间为主要操作；只做公开抽签时以导出为主要操作。是否导出不影响进入赛程的资格。

常用排程资源直接显示，高级设置渐进展开；只读状态禁止修改而不禁止查看设置。赛程选中面板覆盖在侧边，不改变网格坐标；检查、调整方案、确认和命令仍经过原工作流与修订检查。新增呈现不改变 SQLite schema、调度约束或保存事务。

[GUI 设计](superpowers/specs/2026-09-20-v5-beginner-friendly-gui-design.md)仍包含后续完善目标。例如最近赛事历史当前只保存文件路径，界面显示文件名与可用性，不虚构赛事阶段或最后打开时间。本轮证据与未验证边界见 [GUI 本地验证报告](acceptance/v5-gui-2026-10-03.md)。
