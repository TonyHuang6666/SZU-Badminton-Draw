# 5.0 统一赛程编排

5.0 的排程单位是整场赛事，不是一个个独立项目存档。单项目是“只有一个项目的赛事”，与多项目共用同一条工作流、硬约束校验器、赛程板和存储协议。

本说明对应开发分支；当前完成范围见[开发进度](superpowers/plans/2026-09-13-v5-progress.md)。公开抽签与现场记录步骤见[使用说明](usage.md)。

## 进入条件与状态

工作区必须选择“完整赛事筹备”，且全部项目名单有效、抽签已经明确确认。仅公开抽签工作区须先主动升级；升级保留签表，但不生成赛程。

状态按实际数据推进：

| 状态 | 含义 |
| --- | --- |
| 草稿 | 项目及名单尚在准备。 |
| 名单就绪 | 全部名单有效，可逐项预览和确认抽签。 |
| 抽签已确认 | 全部确认签表及比赛关系图存在，但还不要求有赛程。 |
| 赛程就绪 | 一份覆盖全部真实比赛、通过校验的全局赛程已保存。 |
| 进行中 | 至少有一场有效赛果，但尚未全部完成。 |
| 已完成 | 全部需要进行的比赛都有有效赛果。 |

一次导出、一个导入凭据或者“已覆盖全部记录行”均不能代替赛果推动完成状态。

无赛果时可主动重新生成整场赛程；已有赛果后，生成入口锁定，使用赛程板调整未完成比赛。已完成比赛的位置保留，不会为了策略评分而移动。

## 资源只设置一份

- 比赛日期必须唯一，使用真实日期，不以“第一天”等显示文字作为身份。
- 每日开始时间早于结束时间；一场比赛必须完整落在该时段内。
- 场地编号在当天不重复。不可用时段需明确场地、起止时间，不能安排比赛穿过该时段。
- 全局裁判人数可以留空，留空时按可用场地容量；可设置时段容量，零裁判容量表示该时段不能开赛。程序限制的是并发比赛数，不分配具体裁判。
- 最小休息和每日最多场次是整场赛事参数，兼项选手在全部项目合计计算，不存在另外隐含的“多项目 6 场”常量。
- 各项目可设不同预计时长及淘汰阶段时长；这些时长进入真实占用计算，不是显示备注。

页面初始最小休息为 30 分钟、每日上限为 4 场、策略为紧凑完成。这些是可调整的产品默认值，不是对任意赛事的规则建议。组织方应依据自己的规程确定参数，并在首次生成前核对。

团体项目的一个比赛节点表示两支队伍的一场团体对抗。团体子场的队员名单、场序、并行安排与逐子场裁判轮换不在当前调度模型内，不能用总对抗时长冒充这些约束已被验证。

## 硬约束与策略分开

下列硬约束必须通过，不能通过“确认警告”绕过：

1. 所有比赛、项目、双方来源、图版本、时长和位置身份正确，赛程不遗漏真实比赛。
2. 后续比赛不早于全部来源比赛结束；移动前序时也检查已有后继。
3. 同一场地无时间重叠，不超出每日开放范围，不使用不可用场地时段。
4. 各资源边界之间的实际同时开赛数不超过裁判及场地并发容量。
5. 同一选手在相容的晋级路径上不能撞场，且满足全赛事最小休息。
6. 同一选手在相容的胜负路径上不能超过全赛事每日场次上限。
7. 已完成或锁定场次的位置不改变。
8. 同项目名次赛不得晚于冠军决赛的开始时间才开始；这不等于保证所有名次赛在决赛开始前结束。

“相容路径”表示某位选手在同一组胜负事实下确实可能同时出现在那些比赛中。程序不会把互斥的胜者线和负者线全部当成必然出场，也不会把未决占位文字当成姓名跳过检查。单打、双打按各自选手身份参加检查；团体按队伍身份。

策略只在合法位置之间评分：

| 策略 | 主要偏好 |
| --- | --- |
| 紧凑完成 | 更早完成、尽量集中使用前面的资源。 |
| 均衡宽松 | 结合容量和负载目标分散工作量。 |
| 决赛日友好 | 对重要轮次增加末日偏好。 |
| 自定义 | 使用明确的每日负载、阶段推进与重要轮次偏好。 |

单项目时界面称为“项目完成节奏”，多项目时称为“全赛事编排策略”。允许对某项目决赛、半决赛、季军赛和其他名次赛设置末日偏好；即使“强烈偏好”也不是必须落在那一天的硬锁。

自定义每日目标负载和警戒负载是比例，阶段推进是累计比例。阶段同步及末日偏好不能突破资源、依赖或休息规则。生成时会把实际采用的默认策略参数显式保存，便于复查，不依靠界面重新猜测。

改动参数不会自动重排。点击生成才发起求解与保存。“使用策略默认值”只重置编辑参数，仍需主动生成。若其他操作改变了签表、资源或赛程，旧草稿会被标记为冲突，须载入最新设置后再提交。

## 求解失败不等于数学上无解

排程器采用确定性的候选排序与搜索，不是保证全局最优的通用约束求解器。成功必须覆盖全部真实比赛并经过完整硬校验；失败不返回可误存的部分赛程。

失败分为不同证据强度：

- 输入无效：先修正日期、身份、图结构或时长等问题。
- 已证明容量矛盾：例如某选手存在需要打 21 场的合法晋级路径，但五天每天最多 4 场，总容量只有 20 场。此时增加球场无法保障该路径，问题不是球场不足。
- 本次搜索没找到：保留未安排场次、拒绝原因、日容量和建议，但不声称不存在其他可行排法。
- 存储失败：即使内存求解成功，也不能当作已保存；依照提交状态和保留路径处理。

失败不会用新参数和半份赛程覆盖旧工作区。裁判长可据诊断增加比赛日、延长时段、调整场地/裁判或复核预计时长；休息及每日上限必须由组织方明确决定，不会被程序偷偷放宽。

## 手动调整、连锁和撤销

赛程板使用同一份全局位置表。拖动或填写目标仅生成预览；用户检查所有变更后，才确认保存。

单场预览检查当前位置移除后的目标；连锁预览只修复同项目受影响的后继，搜索位置时检查整场赛事。如果后继已完成、没有合法位置或整个变更集校验失败，不能仅保存已经找到位置的前几场。

预览绑定其来源工作区和修订。切换工作区、导入赛果、恢复备份、重新载入或其他有效修改后，不继续使用旧确认。撤销是对当前快照重新验证的单次动作，不是无条件覆盖历史。

保存成功即更新一个工作区，不存在逐一写回多个项目文件导致的部分成功。独立导出的材料文件仍有自己的部分发布边界，不能与数据库原子更新混为一谈。

## 质量报告

质量报告基于完整工作区重新检查，不把之前缓存的“零冲突”当证明。只导出一个项目的材料，也不能绕开其他项目的全局硬错误。

报告保留硬约束明细、每日可用容量及占用、策略与软评分、兼项负荷和相关场次标识。负荷推演有明确边界：

- 已确定场次与相容路径最大场次分开显示。
- 在受限的条件变量规模内，概率分布按等胜率模型精确枚举；“精确”只指该模型的计算，不预测真实选手实力。
- 超出概率枚举边界时，期望和概率显示未知，不写成 0 或伪精确数值。
- 质量里的概率提醒不能豁免每日上限或休息硬约束。

报告不是优化证明，也不是正式赛事合规证书。必须另外核对场馆实际开放、选手身份、组织方规程、裁判人员、关键比赛观赏安排与打印可读性。

## 现场记录与材料不会隐式排程

导入记录表是“预览—确认—保存赛果/凭据”的独立用例，导出材料是另一个独立用例。导入不会自动生成下一日材料，也不会重新计算整场赛程。

材料中的待赛顺延要求明确目标日，依据有效的历史待赛记录和当前未完成状态；仅因某场原计划较早，不能自动把它加入补赛材料。顺延记录保留原计划，目标日的时间和场地为“待安排”，未知实际日期为空；这不更改赛程位置。

记录实际比赛日也不反向改写计划时段。现场真实开赛、结束与人员临时变化仍需裁判长管理；程序的计划硬校验不等于已验证现实中没有延误或撞场。

## 审计与复查材料

建议同时留存原始名单、公开抽签材料及随机种子、工作区、备份、实际交接材料清单和填写后记录表原文件。工作区里保存导出范围、输入文件哈希、有效/作废凭据、更正前后值以及恢复原因。

材料包可能在发布部分文件之后遇到错误，也可能全部文件生成后审计仍未保存。只以提示中的已验证输出及真实提交状态判断，不删除失败现场、不自动重复覆盖。完整操作步骤见[使用说明](usage.md)。
