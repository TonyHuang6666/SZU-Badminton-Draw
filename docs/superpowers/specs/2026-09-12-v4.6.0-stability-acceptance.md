# v4.6.0 稳定性验收规范

## 目标

在功能冻结前提下，对当前 `main` 执行一次可重复、可审计的发布级验收。验收必须覆盖三份仓库样例从名单导入到存档恢复的完整业务链路，并留下机器可读结果、实际 Excel/PDF/SQLite 产物和人工复核记录。

## 验收范围

- 三份样例：159 条双打、29 条双打、29 个学院团体。
- 固定抽签种子，重复生成结果必须一致。
- 单项目排程必须完整，无依赖逆序和严重约束违规，并覆盖不可用场地时间窗。
- 创建并复开三个 `.szbd` 存档。
- 合并三个项目，自动调整跨项目冲突，保存回各存档并导出合并材料包。
- 从每个项目分别导出记录表、确定性填写首批赛果、预览并导入。
- 验证重复导入、冲突更正、后续对阵动态刷新。
- 验证备份恢复、损坏副本拒绝读取和原存档可继续读取。
- 检查 Excel 公式、数据验证、隐藏身份列、LibreOffice 重算错误。
- 检查 PDF 页数、页面尺寸、文本层、字体资源，并渲染代表性页面目视复核。
- 使用固定 .NET 8 SDK 执行锁定还原、依赖漏洞审计、Release 构建、全量测试、桌面启动和发布冒烟。

## 关键边界

- 合并材料包中的记录表没有单一赛事 ID，当前只能用于现场填写、打印和交接；它不能直接导入任一单项目 `.szbd`。赛果回灌必须使用各项目自己的记录表。
- 后续对阵按累计赛果在导出或重新加载时动态解析，不要求改写存档中的原始占位文本。
- 无头验收不能替代真实 Windows/macOS 上的拖拽、撤销、对话框、深色模式和物理打印检查；这些必须在报告中列为人工验收项，不得伪装为已自动覆盖。
- 验收产物写入被 Git 忽略的 `artifacts/acceptance/v4.6.0/`；源代码中的验收驱动与报告纳入版本控制。

## 通过标准

1. 所有自动断言通过，流程返回零退出码。
2. 三个项目的抽签、排程、存档、合并、材料导出、赛果导入和恢复均有结果记录。
3. 合并排程不存在阻断冲突或严重违规。
4. 重复导入被识别；冲突赛果在未授权时被阻止，授权更正后留下历史记录。
5. 备份恢复还原结果、已处理比赛日和导入日志，同时保持赛事身份、参赛者和合并后的赛程位置。
6. 依赖漏洞审计无已知漏洞；全量构建、测试、启动和发布冒烟通过。
7. 报告准确区分自动通过、人工通过、未执行和明确不支持。
