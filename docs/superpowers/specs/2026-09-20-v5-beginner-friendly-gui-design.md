# v5.0 面向普通用户的赛事助手式 GUI 设计

日期：2026-09-20  
状态：待用户复核设计文档  
适用分支：`feature/v5-unified-workspace`

## 1. 背景与目标

v5.0 已具备赛事创建、名单导入、公开抽签、统一排程、现场材料、赛果导入和备份恢复等完整能力，但当前界面按内部数据结构和管理功能组织，普通羽毛球爱好者需要先理解“工作区、发布快照、覆盖、审计”等术语，才能判断下一步应做什么。

本次改版将界面从“功能菜单”改造成“赛事助手”：始终告诉用户当前做到哪一步、下一步要做什么、完成后会得到什么。改版不改变调度算法、赛事数据模型、存档格式和既有安全规则。

## 2. 目标用户

主要用户是临时负责校内、社团或业余羽毛球比赛的组织者。他们熟悉比赛流程，但不一定了解专业赛事软件、数据库或调度算法。

设计应满足：

- 第一次打开程序即可判断从哪里开始；
- 不阅读使用说明也能完成一场常见单项赛；
- 公开抽签可以独立完成、确认并导出，之后再继续安排赛程；
- 单项目与多项目使用符合各自实际决策方式；
- 高级赛事管理员仍可访问全部现有能力；
- 关键数据操作可预览、可确认、可恢复。

## 3. 设计原则

### 3.1 以任务表达，不以内部对象表达

主界面使用“比赛、赛事文件、安排比赛时间、现场材料”等用户语言。“工作区、快照、审计、覆盖”等术语仅在高级说明或技术详情中出现。

### 3.2 每个页面只有一个主要下一步

页面底部固定显示与当前状态匹配的主操作，例如：

- `下一步：导入参赛名单`
- `名单检查无误，开始公开抽签`
- `导出抽签结果`
- `继续安排比赛时间`
- `生成现场比赛材料`

返回、重新加载、修改历史和恢复等操作使用次要样式，不与主操作竞争。

### 3.3 先展示常用选项，再按需展开高级设置

默认页面只展示完成当前任务所必需的内容。不可用时段、负载目标、阶段进度、分段时长、分页细节和审计信息放在明确命名的“高级设置”或“技术详情”中。

### 3.4 系统状态必须可理解、可行动

错误和警告先说明发生了什么、数据是否安全、用户下一步可做什么。底层异常仅放在可展开的技术详情中。

### 3.5 尊重公开抽签的独立流程

抽签后必须停留在结果确认环节，允许公开展示和导出。程序不得因为选择了“完整赛事筹备”就自动跳过抽签结果确认。

## 4. 整体信息架构

赛事主流程统一为六步：

1. `创建比赛`
2. `准备参赛名单`
3. `公开抽签`
4. `安排比赛时间`
5. `比赛现场`
6. `完成与归档`

每一步显示以下状态之一：

- `未开始`
- `进行中`
- `已完成`
- `需要处理`

步骤之间使用连续的进度轨道表达先后关系。尚不可进入的步骤显示未满足条件，并通过短说明告知原因，而不是只显示灰色禁用按钮。

## 5. 应用外壳

### 5.1 顶部区域

打开赛事后，顶部只保留：

- 赛事名称；
- 当前阶段；
- 保存状态：`正在保存…`、`已保存`、`保存失败`；
- 一个“更多”菜单，包含返回首页、打开其他赛事、备份与恢复和赛事文件信息。

首页不显示赛事阶段侧栏。进入“新建比赛”时，也不残留之前已打开赛事的导航和路径。

### 5.2 左侧赛事进度

左侧导航改为六步进度轨道。每项包含编号、名称和状态。当前步骤使用强调色；已完成步骤使用完成标记；需要处理的步骤使用警示标记。

侧栏底部仅显示简洁保存状态，不直接显示完整文件路径。

### 5.3 页面内容结构

所有流程页采用一致结构：

1. 页面标题；
2. 一句说明“这一步要完成什么”；
3. 当前状态或待处理提醒；
4. 主要内容；
5. 高级设置；
6. 固定底部操作栏：返回、主要下一步。

## 6. 首页与新建比赛

### 6.1 首页

首页突出两个选择：

- `创建一场新比赛`
- `继续上次比赛`

最近赛事以名称、当前进度、上次打开时间和主按钮显示。无效或已移动的最近赛事不显示数据库错误，而显示：

> 找不到这个赛事文件。它可能被移动或删除。

提供 `重新选择文件` 和 `从最近列表移除`，技术错误放入详情。

备份恢复作为次要入口显示为“恢复以前的比赛”。

### 6.2 新建比赛

新建流程保留三步，但改为普通用户问题：

1. `这是什么比赛？`
2. `要进行哪些项目？`
3. `把赛事文件保存在哪里？`

首屏选择：

- 比赛名称；
- 团体赛或单项赛；
- 本次先做什么：
  - `先完成公开抽签`
  - `从抽签到现场，筹备整场比赛`

选项使用可点击说明卡，而不是只有单选按钮和长段落。团体赛与单项赛不得同时选择。

## 7. 名单与抽签

### 7.1 准备参赛名单

页面按项目展示状态卡：

- 尚未导入；
- 已导入多少人或组合；
- 有多少条需要检查；
- 种子设置是否完成。

默认只显示导入模板、导入按钮、检查结果和种子设置。原始解析信息和高级名单操作折叠显示。

所有项目符合要求后，主按钮变为 `名单检查无误，开始公开抽签`。

### 7.2 公开抽签

抽签页分成三个明确阶段：

1. `抽签前检查`
2. `执行公开抽签`
3. `确认并导出结果`

执行前显示项目、人数、种子和抽签方式摘要。执行后保留结果预览，必须由用户确认，才标记为抽签完成。

抽签结果确认后提供两个并列但含义明确的动作：

- 主操作：`导出抽签结果`
- 后续操作：`继续安排比赛时间`

选择“先完成公开抽签”的赛事到这里即可结束当前工作，首页显示“抽签已完成，可以以后继续筹备”。

## 8. 单项目与多项目排程

### 8.1 单项目

只有一个项目时，允许选择项目排程偏好：

- `尽快完成`
- `时间安排均衡`
- `重要比赛集中在最后一天`

每个选项附带一句结果说明，界面不只显示抽象名称。

### 8.2 多项目

有两个或以上项目时，不显示单项目的独立排程偏好。页面明确说明：

> 多个项目会共享时间、场地和参赛人员，程序将统一安排全部项目。

普通设置只包含：

- 比赛日期；
- 每天开始和结束时间；
- 可用场地；
- 各项目预计单场时长。

不可用场地时段、裁判人数、负载比例、累计阶段目标、分段时长和决赛日细节放入“高级排程设置”。

生成前展示容量检查摘要：预计比赛数量、可用场次、主要冲突和是否可生成。主操作为 `检查并生成赛程`。

## 9. 赛程板

赛程板默认用于查看。顶部提供日期切换、缩放和问题筛选。

用户选择一场比赛后，在侧边或底部出现“调整这场比赛”，包含目标日期、时间和场地。系统先用普通语言解释影响：

> 移动这场比赛还会影响另外 2 场比赛。

用户可查看详细变化后确认。现有单场移动、连锁移动、预览、撤销和回滚能力保持不变，但不在默认视图同时展开全部控件。

## 10. 比赛现场与完成

现场页面不再以“赛果导入 / 材料导出 / 只读记录”作为第一层结构，而按实际顺序显示：

1. `导出比赛材料`
2. `记录或导入比赛结果`
3. `查看更新后的后续对阵`

高级导出范围、跨日待填记录、PDF 分页和覆盖确认放入高级设置。操作前仍保留范围确认和覆盖保护，但文案说明其作用。

“完成与归档”汇总：

- 各项目完成状态；
- 尚未填写的结果；
- 最近备份；
- 导出最终材料；
- 创建归档备份。

原始审计记录仍可在高级区域查看。

## 11. 语言与错误处理

文案遵循以下规则：

- 一个按钮只表达一个动作；
- 避免单独使用内部术语；
- 说明结果，不只说明系统动作；
- 警告必须给出建议；
- 危险或覆盖操作说明影响范围。

例如：

| 当前表达 | 新表达 |
| --- | --- |
| 新建赛事工作区 | 创建一场新比赛 |
| 打开赛事工作区 | 打开已有比赛 |
| 全局赛程设置 | 安排比赛时间 |
| 现场执行 / 完成 | 比赛现场 |
| 发布快照 | 确认并启用当前赛程 |
| SQLite Error 14 | 无法打开赛事文件；请重新选择文件或从备份恢复 |

技术详情保留错误代码、异常内容和文件路径，便于诊断，但默认折叠。

## 12. 视觉与无障碍

- 保留现有浅色和深色主题；
- 强调色只用于当前步骤和主要操作；
- 成功、警告和错误不能只依赖颜色，必须同时有图标或文字；
- 常用按钮保持足够点击面积；
- 表单标签始终可见，不仅依赖占位文字；
- 键盘焦点顺序符合视觉顺序；
- 控件继续提供清晰的自动化名称；
- 长路径、技术文本和大量审计信息不得挤压主要内容。

## 13. 技术边界

本次允许修改：

- Avalonia 应用外壳、页面布局和样式；
- 页面级与导航级 ViewModel；
- 面向用户的文案、状态映射和错误映射；
- 与新导航和渐进式展示相关的 UI 测试；
- 使用说明和截图。

本次不修改：

- 核心抽签和排程算法；
- SQLite 数据模型和 `.szbd` 格式；
- 导入导出文件格式；
- 既有备份、回滚、审计和冲突保护语义；
- 团体赛与单项赛同时进行的支持范围。

## 14. 验收标准

### 14.1 首次使用

- 首页只有一个明显的新建入口和一个明显的继续入口；
- 新建流程不会显示旧赛事的侧栏、状态或路径；
- 普通用户无需理解“工作区”即可完成创建。

### 14.2 流程引导

- 打开赛事后始终能看到当前步骤、完成状态和下一步；
- 不满足前置条件时，界面说明缺少什么；
- 每个流程页最多突出一个主操作。

### 14.3 抽签独立性

- 抽签结果必须经过确认；
- 确认后可导出并停止，不会自动进入排程；
- 以后重新打开仍能继续完整赛事筹备。

### 14.4 排程模式

- 单项目显示项目排程偏好；
- 多项目不显示无意义的单项目偏好；
- 多项目明确说明采用统一排程；
- 普通设置可完成常见排程，高级设置不丢失原能力。

### 14.5 错误与数据安全

- 最近赛事失效时不直接显示 SQLite 英文错误；
- 保存失败、导入冲突和覆盖风险均说明数据状态与处理建议；
- 技术详情仍可用于问题诊断；
- 所有核心回滚、备份和审计测试继续通过。

### 14.6 验证

- Windows 与 macOS 均可构建；
- 现有测试全部通过；
- 新增导航、状态、单/多项目排程展示、抽签停留和错误映射测试；
- 实际运行检查浅色与深色主题；
- 截图核验首页、新建、名单、抽签、排程、赛程板和现场页。

## 15. 实施顺序建议

1. 建立统一的步骤状态与通俗文案映射；
2. 重构应用外壳、首页和新建流程；
3. 重构名单与公开抽签流程；
4. 分离单项目和多项目排程展示；
5. 简化赛程板默认操作；
6. 按现场动作重组材料和赛果页面；
7. 统一错误、保存状态和技术详情；
8. 完成自动化测试、双主题截图和端到端验收。
