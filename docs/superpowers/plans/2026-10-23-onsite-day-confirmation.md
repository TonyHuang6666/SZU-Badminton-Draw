# 现场记录与逐日确认实施计划

用户已确认设计并授权实施。只操作源码和临时测试数据，不修改真实赛事文件，不提交、推送或发布。

## 规则

- 胜方和比赛结果（正常、弃权）是必填项，二者选择后立即保存；比分、时长可为空，后续补齐。
- 日确认与导入覆盖 ProcessedDays 分离，持久化独立事实。原有 Excel 导入流程保留，导入不自动确认日期。
- 现场窗口只列已确认日期和最早未确认比赛日。历史日期允许补充元数据；下一日需显式确认当前日后解锁。
- 确认时全部场次应有结果，或逐场声明经裁判长同意延期及原因。延期不是弃权或赛果。
- 延期场次尝试放入下一个配置的比赛日；相关后继合并计算，已完成及无关场次保持原位。遵守场地、裁判、休息、每日上限和依赖规则。
- 先预览，再一次提交赛程、确认记录、审计。失败不确认、不部分移动；没有下一比赛日时阻止延期确认并说明限制，已有赛果时不通过重新生成赛程新增日期。
- 历史比分/时长从空白补齐无需更正理由；修改已有值继续保留更正保护。胜方修改沿用现有安全限制，不自动清除后继赛果。

## Task 1: 可选赛果元数据

负责 Core TournamentMatchResult/TournamentResultRules、结果导入解析与评估、Excel 导出、相应 backend 测试。
DurationMinutes 改 int? 表示未填。正常赛果允许空比分及空时长；已填写仍验证。弃权允许空或0，拒绝正时长。空字段导出为空。
空 -> 合法值为补齐，复用历史审计但不要求更正授权；覆盖已有值/改变结果种类或实际日仍需保护。Excel 与原生路径共用规则。
先写覆盖测试，再实现。不要修改 Desktop、Workspace/持久化/排程/日确认文件（Task 2 拥有）；测试构建由主代理串行运行。

## Task 2: 日确认和原子延期后端

负责新增 Core 日确认模型及规则、Workspace 属性、持久化、Workflows 日确认和多根延期预览算法、排程编辑确认保护、backend 测试。
提供 WorkspaceDayConfirmation 等持久事实及查询帮助；PreviewDayConfirmation(request, expectedRevision) 返回不可伪造、只读预览；ConfirmDayResults(preview, expectedRevision) 验证当前来源后一次 CommitChange。
请求包括 DateOnly Day 和每个延期 MatchKey 的 Reason/裁判长同意事实；预览有 Changes、Warnings/Errors、CanConfirm、已完成数/延期数。
公布精确 API 后主代理接 UI。不要修改结果模型/解析器/Excel/OnsiteResults 或 Desktop（分别 Task 1 /主代理负责）。构建由主代理串行运行。
验证连续日期确认、持久化往返、延期依赖合并、容量不足原子失败、过期预览、保存失败、最后比赛日、已有确认日防回填、元数据补充保持确认。

## Task 3: 原生交互

主代理负责 Desktop 现场记录 VM/Shell。结果选择完整触发保存，保留异步过程中后续输入；可选补充与失败草稿可重试。
负责日期限制、当天汇总、确认预览与延期原因、明确保存状态。确认前排空保存队列。日确认后无全部日期旁路。
补充 viewmodel/window 回归，保留 Excel 入口与已有浮窗体验。
