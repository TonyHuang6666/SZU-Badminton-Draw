# 公平性与公开审计

公平性需要同时说明“抽签如何产生”“赛程为何这样安排”以及“现场记录如何影响赛事”。本页面向裁判长、赛事干事和参赛代表，给出可公开复核的材料与流程。算法细节见[算法说明](algorithm.md)，规则适用范围见[竞赛规则对应关系](rules-compliance.md)。

## 抽签公平性的组成

程序把随机分配与赛事约定结合起来：

- 各组人数均衡，人数差不超过 1。
- 种子按组织方提供的序号参与分组和淘汰树保护。
- 同单位参赛方尽量分散；双打双方单位都会参与判断。
- 淘汰赛逐组计算首轮赛和直接晋级位置。
- 名单、设置、随机种子和算法实现相同时，分组和签位可复现。

这些目标有明确的优先级。分组时先比较同单位冲突数，再考虑种子首选组距离和当前人数；小组容量始终限制候选位置。因此“种子保护”和“同单位回避”需要结合实际签表检查。程序没有承诺所有合法签表等概率，也没有求解全局最少的同单位冲突。

## 公开随机种子与复现

随机数种子是一段公开字符串，用来驱动稳定洗牌。建议在名单、种子名单和赛制设置公示后，再由裁判长与参赛代表按事先约定的方法产生随机种子，并保存见证记录。

复现需要以下信息完全对应：

| 输入 | 核对内容 |
| --- | --- |
| 名单 | 参赛方及原顺序、显示名称、双方姓名和学号、双方单位。 |
| 种子 | 是否种子、种子序号和组织方确定种子的依据。 |
| 赛制 | 单打/双打/团体、循环/淘汰、组数、淘汰目标和名次附加赛。 |
| 随机过程 | 随机种子、算法版本和使用的程序版本。 |
| 保存结果 | 实际采用的设置、生成时间和正式确认时间。 |

例如 29 队分 8 组，“每组出线”产生 8 个出线名额，“决出冠军”还包含跨组冠军段。应核对结果中实际采用的目标，不能仅凭组数判断终点。

重复运行有助于复核结果，但公开随机种子本身无法说明组织方是否曾尝试其他种子、改变名单顺序或多次抽签。现场应先约定重新生成的条件，记录每次生成及其原因，及时公示正式确认材料。复现时比较分组、签位和晋级关系；生成时间及新工作区 GUID 可以不同。

## 三种哈希如何使用

| 信息 | 用途 | 阅读边界 |
| --- | --- | --- |
| 原始名单文件 SHA-256 | 确认保存的文件字节与导入来源一致。 | 界面中的种子调整保留原始来源哈希，应同时查当前名单与种子编辑审计。 |
| 抽签输入 `InputHash` | 比较有序名单及抽签设置的序列化内容。 | 随机种子单独保存；相同输入哈希可以对应不同抽签结果。 |
| 导出文件 SHA-256 | 赛事存档内部的导出审计保留文件哈希，用于核对当次发布记录。 | 材料包说明列出文件名称；使用办公软件编辑或重新保存文件后，字节哈希通常改变。 |

抽签输入哈希覆盖赛制、项目类型、组数、算法版本、淘汰目标、名次附加赛，以及有序名单中的显示名称、种子标记/序号、双方姓名/学号和单位。备注不参与抽签输入哈希；原始文件哈希仍覆盖文件本身。

哈希提供内容一致性依据，不提供组织者身份签名或不可篡改的公开时间证明。工作区中的审计和备份、原始材料、现场见证及公示记录需要共同留存。

## 种子、同单位与轮空的核对

种子人选由组织方根据比赛规程、成绩或技术水平确定。程序按参赛方数量限制种子上限：

| 参赛方数（人/对/队） | 最多种子数 |
| ---: | ---: |
| 1—15 | 2，且不超过参赛方数 |
| 16—31 | 4 |
| 32—63 | 8 |
| 64—128 | 16 |
| 129 及以上 | 32 |

种子序号越小，排序越靠前。序号必须为允许范围内的不重复正整数；只标记种子而未编号会出现提醒。公开抽签前应补齐排名序号，并确认同批次种子排序的产生方式。

淘汰树使用内置保护位置，例如 16 签位为 1、16、5、12；32 签位为 1、32、9、24、5、13、20、28。首轮赛和直接晋级位置逐组计算，已编号高位种子优先获得直接晋级位置；该组直接晋级名额不足时，部分种子须参加首轮赛。完整位置表和计算例子见[算法说明](algorithm.md)。

“学院/学部”和“搭档学院/学部”提供同单位信息。组织方应统一单位写法；程序不会自动把简称、院系别名或不同层级名称识别成同一单位。双打任何一方单位重合都会计为同单位。单项循环赛优先列出同单位对阵，团体循环赛使用普通轮转顺序。

单位分散不能决定谁是种子，也不能保证同单位永远不交手。最终签表还应检查组内人数、种子位置、首轮对手以及直接晋级分布是否符合已经公布的校园赛事规程。

## 建议的公开抽签流程

1. 公示报名名单及身份信息，核对姓名、学号、搭档和单位，处理重复或歧义。
2. 公示种子名单及序号，确认小组数、淘汰目标和名次加赛范围。
3. 记录使用的程序和算法版本，现场产生并公布随机数种子。
4. 主动生成抽签结果，查看分组和签位；需要时导出待确认抽签材料。
5. 核对实际采用的赛制设置和提醒。结果符合约定后，明确确认抽签，再导出正式材料。
6. 公示随机种子、输入哈希、生成/确认时间以及正式签表，保存原始名单与见证记录。
7. 仅公开抽签的赛事可在此结束；需要安排赛程时，显式升级同一工作区的工作目标。
8. 如需变更，按规程决定处理方式并记录原因。无赛果时解除确认会清除该项目比赛图和全赛事赛程，并作废相关待赛凭据；已有赛果后禁止通过解除确认入口重抽。

确认表示把该项目签表固定为后续比赛图和材料的依据。编辑框中的草稿、待确认抽签结果和已确认签表有不同状态，公示时应标明采用哪一份。

## 赛程公平性与身份

单项赛按真实选手身份跨全部项目排程。学号是主要身份依据；缺少学号时按规范化姓名识别。男双、女双和混双的双方分别参与兼项检查。相同学号出现在多个项目时代表同一位选手，应先核对录入是否准确。

在时间安排上，共享校验约束：

- 比赛位于输入的日期、开放时间、可用场地和裁判容量内。
- 同场地和同选手的比赛不能重叠，后续比赛须等待来源比赛结束。
- 单项选手跨全部项目满足设置的最小休息和每日最多场次。
- 同项目名次赛的开始时间不晚于冠亚军决赛开始时间。
- 已完成及明确锁定的比赛位置保持固定。

桌面以尽快完成的紧凑安排为基准。多项目单项赛可勾选“将各项目决赛安排在最后一个比赛日”，把冠亚军决赛放到资源中实际日期最晚的一天。这个开关是组织方选择的硬条件；其他轮次仍按资源和依赖安排。默认最小休息 30 分钟、每日上限 4 场只是软件输入初值，组织方须按赛事规程确认。

团体赛按整场队伍对抗排程，桌面使用统一对抗时长，不应用个人休息和每日场次限制。同一队伍不能同时参加两场对抗；队内谁上场、子场顺序、队员兼项与休息均须另行核对。

## 未决比赛的负荷如何解释

淘汰赛在胜负确定前，每位选手可能沿不同路径晋级。程序只合并能够同时成立的路径：同一场比赛的胜者线与负者线互斥，同一位选手跨男单和男双的路径却可能同时发生。

因此，某位选手存在一条合法赛果路径导致撞场、休息不足或当日超量，就属于需要处理的硬问题。概率较低不会解除硬限制；录入赛果后，路径范围会按已确定的胜负收窄。

质量报告的“选手每日负荷”按选手和计划日期列出已确定出场数、最大可能出场数及未完成计算说明。“已确定”指当前计划中确定会参赛的场次，与已完成场次含义不同；最大可能出场数考虑能够实际连续参与的晋级路径。最大值尚未算出时，说明会列出已证明至少、至多可能参加多少场，不能把上界当成已证明的最大值，也不能把未知理解为零风险。底层概率模型的技术范围见[算法说明](algorithm.md)。

自动排程找到的是满足已表达条件的方案。搜索有有限预算，失败可能表示输入问题、有证据的容量不足，或本次搜索尚未找到完整方案。增加场地可以缓解资源并发问题，但无法解决同一选手在既定天数和每日上限下的总场数矛盾。

## 建议的赛程审计流程

1. 在同一工作区核对全部项目已确认的签表，检查兼项选手身份。
2. 核实实际比赛日期、开放时间、场地、不可用时段、裁判容量、各项目时长及单项选手负荷设置。
3. 生成一份全局赛程，检查报告中的硬校验状态、日利用率、个人负荷和未完成统计。
4. 在赛程板检查重点轮次、兼项、连续比赛和场馆切换；移动或连锁调整应先审阅完整预览再保存。
5. 明确导出的项目、比赛日和可选待赛目标日，生成材料包。导出校验覆盖全赛事，筛选范围只决定文件内容。
6. 核对赛程明细、时间场地网格、带时间对阵表、记录表和计分材料，确保场次与来源对应。
7. 对照“材料包说明”中的文件列表和工作区内部保存的导出审计，确认哪些文件已成功发布；部分文件成功不能代表整个材料包已完成。
8. 保存手动备份、正式材料和填写后的记录表原文件；赛果导入、更正或恢复后，交接最新工作区与相应材料。

已有赛果后，整场重新生成被禁止。已完成比赛锁定，未完成场次可通过全局校验的移动或连锁预览调整。程序记录的实际比赛日、原计划日及记录表目标日具有不同用途，赛后审计应分别核对。

## 留档与赛果证据

建议将以下资料放入赛事交接目录：

| 资料 | 审计用途 |
| --- | --- |
| 原始报名表及确定种子的依据 | 说明参赛资格、身份和种子来源。 |
| 随机种子产生记录、正式抽签 Excel/PDF | 复核抽签输入、签位和确认状态。 |
| 当前 `.szbd` 及有效备份 | 继续赛事，查看统一状态、赛果和操作审计。 |
| 赛程材料及材料包说明 | 核对当时发布的项目、日期、时间场地和文件列表；文件哈希保存在赛事内部导出审计中。 |
| 填写后的记录表原文件 | 复核导入来源、比赛行位置、原始填写值和实际比赛日。 |
| 更正、调整与恢复原因 | 说明材料和赛事状态为何发生变化。 |

记录表导入会核对赛事和比赛身份，并按依赖解析整个批次。同一文件重复导入为无变更；无胜方的有效行可以形成待赛凭据。胜负冲突会阻断批次，允许的元数据更正须明确批准并记录原因、前后值及来源位置。辅助显示公式不作为胜负身份依据。

材料包说明中的文件列表用于交接核对，赛事内部导出审计保存文件大小、哈希和导出范围，工作区保存当前可继续操作的赛事状态。多文件发布出现故障时，应按实际结果保留已发布文件和暂存证据；恢复备份会产生新的修订与恢复审计。详细故障边界见[故障排查](troubleshooting.md)。

## 组织方仍需判断的事项

- 参赛资格、种子人选、同批次排序及正式规程的适用版本。
- 退赛、替补、重抽和循环赛最终名次及同分判定。
- 比赛计分办法、个人实际体能、团体内部场序和阵容。
- 真实场馆预约、裁判资格与轮换、记分员和志愿者安排。
- 选手个人不可用时间、跨校区交通、天气、延误及重点场次的现场需求。

软件能校验模型中明确输入的条件。赛程发布仍需裁判长和组织方审定；有据可查的输入、公开过程和完整交接共同支撑赛事公平性。
