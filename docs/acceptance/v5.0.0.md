## 2. 产品架构结果

5.0 已将入口改为“先定义赛事，再选择工作目标”：

- 一个工作区只承载团体赛或单项赛，不支持两者同时进行。
- 单项赛可包含一个或多个项目；只有单项目使用项目完成节奏，多项目使用全赛事策略。
- “仅公开抽签”与“完整赛事筹备”在新建时显式选择；导入名单不会自动抽签或排程。
- 抽签预览、预览材料导出、确认抽签、正式材料导出互相独立；公开抽签后可以关闭并稍后继续。
- 整场赛事使用一个 `.szbd` 工作区；所有项目共享比赛日、场地、裁判容量、休息和每日场次上限，不再先排多个存档再合并。
- 比赛关系图、时间位置和现场赛果分层存储；未决胜者/负者路径仍参与兼项和容量判断。
- 桌面唯一入口为 Avalonia `AppShellWindow`；旧 `MainWindow`、旧单项目调度、多存档合并和旧记录读取路径已删除。
- SQLite 生产依赖只由 Persistence 工程直接持有，桌面与 Excel 工程不直接引用 SQLite。

5.0 工作区 schema 为 500。按用户决定，本版本不读取或迁移 4.x 存档；旧赛事应继续使用对应旧版本打开。

所有子进程均 `exit=0`、未超时。每条流程保存阶段日志、受管读回、文件长度与 SHA-256、工作区和备份；缺失产物不能通过清单验证。

292 场样例由 64 人男单（68 场）、32 对男双（112 场）和 32 对混双（112 场）组成，使用七个比赛日、16 片场地、12 名裁判、30 分钟休息、每人每日最多四场以及 20/25/30 分钟项目时长。输出恰有 292 个位置，赛程验证 `IsValid=true`，硬约束与违规均为 0。本地耗时不是其他机器或规模的性能承诺。

345 场样例被拒绝的核心证据为：同一选手存在至少 21 场可同时成立的参赛路径，而五个比赛日乘每日四场只容纳 20 场。诊断明确建议增加比赛日，并指出只增加场地、裁判或延长每日时段不能解决总场次容量矛盾。

## 4. 赛果、故障与数据安全

- 赛果导入按工作区、项目、比赛、签表版本及源文件哈希绑定；相同文件重复导入不重复保存。
- 相反胜方被阻止；赛果元数据更正需要明确确认和原因，并保留前后历史。
- 记录表支持待赛覆盖、跨日来源、反序文件和胜者/负者后续对阵；互相矛盾的新文件阻止整批提交。
- 调度编辑覆盖单场、连锁、跨日、不可用资源、撤销及复开后基线；已记录比赛不能被普通移动改写。
- 工作区写入使用候选副本、事务校验、备份和替换。最终验收实际触发 `SQLite Error 19`，确认原工作区未被替换。
- 故障矩阵覆盖未提交候选复制、真实事务失败、发布失败、部分备份、提交后重读失败、手工备份审计失败、材料部分发布、材料审计失败、健康/损坏恢复、修订或源字节过期、恢复后撤销失效及四类畸形待赛单元格。
- 材料文件和工作区审计不伪装成跨文件原子事务；失败结果区分已验证输出、状态未知目标、暂存目录、候选、备份和真实提交状态。

## 5. Excel、PDF 与材料验证

本次端到端运行生成的 100 个 XLSX 和 25 个 PDF 全部通过程序受管读回、结构与哈希检查；验收结果中的 `Office` 和 `PdfVisual` 仍诚实记录为 `NotRun`，因为这一次运行没有另行启动办公软件或逐页人工查看。

在同一实现的固定七场景材料批次中，另有以下独立证据：

- 73 个必需产物：44 个 XLSX、15 个 PDF、7 个说明和 7 个清单；全部与真实保存的 SQLite 导出审计逐一匹配。
- 44 个工作簿的 LibreOffice 副本完成重算，共 113 个工作表、40 个公式、50 行记录；200 个独立推导的 F/H/O/P 值全部匹配，无公式错误或受保护标识丢失。
- LibreOffice 副本共 129 页，机器检查全部完成；其中 28 页实际渲染并查看，剩余 101 页仅机器检查。
- 程序原始 15 个 PDF 共 26 页，26/26 均实际渲染查看；字体、ToUnicode 和纸张结构检查通过。
- 时间对阵 PDF 的默认布局 12 页和复杂样例拼页 6 页均查看；另 11 页拼页产物只做机器检查。

这些材料样例来自隔离的合成工作区，不应被描述为真实报名文件；LibreOffice 也不能替代 Microsoft Excel。复杂淘汰图拼页可能切开连接线或单元格，宽记录表可能不适合手写，正式赛事仍必须打印预览。

## 7. 明确未执行的门禁

1. 远端 GitHub Actions 尚未由本分支触发；Windows/macOS CI 状态不能写成通过。
2. Windows 真机启动、原生文件选择器、显示缩放、深色模式和完整操作链尚未执行。
3. Microsoft Excel 重算尚未执行；已有办公软件证据来自 LibreOffice。
4. 本次 586 文件验收没有完成全部 PDF 页面的人工视觉矩阵；逐页范围以第 5 节为准。
5. 物理打印、现场网络会议抽签、多人交接和真实赛事压力测试尚未执行。
6. macOS Developer ID 签名、公证和 Gatekeeper 下载场景尚未执行。
7. Linux 不在 5.0 正式支持/验收矩阵内。
