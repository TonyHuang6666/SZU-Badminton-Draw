# 深大羽协羽毛球赛事工作台

面向 Windows 和 macOS 的校园羽毛球赛事工作台：名单核对、公开抽签、统一排程、现场记录、材料导出和备份恢复。

本分支正在开发、验收 5.0，尚不是已发布的稳定版本。历史 4.6 的交付记录见 [4.6 发布说明](docs/releases/v4.6.0.md)；5.0 的已完成项、验证证据和未完成项见 [开发进度](docs/superpowers/plans/2026-09-13-v5-progress.md)。以下说明面向 5.0 的工作方式，不沿用 4.x 的操作入口。

## 5.0 的核心变化

先决定办什么比赛，再决定今天做到哪一步。

- 一个赛事工作区只举办团体赛或单项赛，两者不能混排。团体赛包含一个团体项目；单项赛可从男单、女单、男双、女双、混双中选择一至五项。
- 新建时选择“仅公开抽签”或“完整赛事筹备”。即使选择完整赛事，导入名单也不会自动抽签，更不会自动排程。
- 抽签预览、导出预览、确认抽签、导出正式抽签材料是独立动作。可以在公开视频会议中完成抽签和公示后关闭程序，以后再继续排程。
- 一场赛事只有一个 `.szbd` 工作区，包含全部项目。单项目和多项目使用同一套排程器、全局资源和选手身份，不再先分别排程、再合并多个存档。
- 单项目时设置“项目完成节奏”；多项目时设置“全赛事编排策略”。项目可以有不同预计时长和重要轮次偏好，但不能各自占用一套互相冲突的时间、场地。

## 快速开始

1. 新建工作区：填写名称，选择团体赛或单项赛、工作目标、项目及赛制，选择本地 `.szbd` 保存位置。
2. 名单准备：按模板导入各项目名单，核对学号、搭档、单位和种子。全部项目名单通过检查后进入公开抽签。
3. 公开抽签：逐项确认分组和随机种子，主动生成预览；检查或导出未确认预览后，再明确确认并导出正式抽签材料。到此可以结束本次工作。
4. 统一排程：仅公开抽签工作区先升级为完整赛事；全部项目抽签确认后，设置共同比赛日、场地、裁判容量、休息和每日场次上限，主动生成赛程。
5. 赛程调整：在同一赛程板中预览单场或连锁移动，查看所有变更后确认保存；可撤销上次移动。已完成场次锁定。
6. 现场执行：按项目、日期选择材料范围并导出；回收填写后的记录表，先预览诊断，再确认导入。导入赛果与导出材料互不自动触发。
7. 备份与恢复：重要操作前主动创建备份；需要恢复时，核对备份身份、修订和哈希，填写原因并确认。

详细步骤和填写限制见 [使用说明](docs/usage.md)，资源、策略及失败处理见 [赛程编排说明](docs/scheduling.md)。

## 文件与安全边界

| 文件 | 用途 |
| --- | --- |
| `.szbd` | 整场赛事的可信状态，含全部项目、确认签表、全局赛程、赛果、导入凭据与审计；不要直接编辑数据库。 |
| 名单 `.xlsx` | 报名输入。学号用于跨项目识别，双打必须分别填写两名选手。 |
| 记录表 `.xlsx` | 现场填写和赛果导入；保留隐藏标识、公式与原计划信息。 |
| 其他 `.xlsx`、`.pdf`、`.png`、`.jpg` | 公示、审计、交接或打印，不是另一个赛事状态来源。 |

5.0 使用新工作区格式，不读取或迁移 4.x 存档。不要用 5.0 覆盖旧文件；需要试用时从名单新建工作区，旧文件继续由对应版本读取。

工作区更新使用受校验的候选副本、备份和文件替换；失败会区分“未提交”与“已保存但重读失败”。材料文件与工作区审计不是一个跨文件事务：可能已经产生部分文件，但整包未完成或审计未保存。遇到错误应保留提示中的候选、备份和暂存路径，核对后处理，不要仅凭文件存在判断成功。

记录表导入按工作区、项目、比赛及签表版本核对身份，按文件内容哈希识别重复输入。胜负冲突不会被静默覆盖；允许的赛果元数据更正需要明确确认和原因，保留更正前后证据。没有胜方的待赛记录不等于比赛已完成。

## 导出与打印

公开抽签支持 Excel、A4 PDF、PNG、JPEG 或全部格式，区分未确认预览和正式抽签材料。

现场材料包按明确范围生成带时间场地对阵表、项目记录表、每日赛程与合并记录表、单项计分 PDF 或团体计分 Excel，并包含全赛事质量报告、说明和文件清单。文件名使用项目标识、材料种类和日期；同名项目也不靠名称推断身份。材料清单记录实际范围、跳过项、字节数和 SHA-256；完整成功以工作区中保存的导出审计为准。

打印前必须预览。复杂对阵图默认整图缩放可能偏小；增加 PDF 拼页可以放大，但会切开连接线或单元格，需要按顺序阅读或拼接。部分宽记录表不适合直接作为手写计分纸，请使用专用单场计分表。质量报告的不同工作表可能采用 A4 或 A3，不要把全部表强行打印成一张 A4。

## 架构与开发

- `BadmintonDraw.Core`：抽签、类型化比赛关系图、赛事状态、不变量和全局调度。
- `BadmintonDraw.Persistence`：SQLite 工作区存储、版本检查、备份与恢复。
- `BadmintonDraw.Excel`：名单和记录表读写、实际材料版式与图像/PDF 渲染。
- `BadmintonDraw.Workflows`：唯一赛事用例入口，协调校验、存储、导出及审计。
- `BadmintonDraw.Desktop`：Avalonia 桌面壳及各阶段页面。
- `tests`：核心、存储、工作流、故障和桌面生命周期测试。
- `tools/BadmintonDraw.Acceptance`：有界端到端验收及证据产物；不替代桌面和实际打印验收。

开发使用 `global.json` 指定的 .NET 10 SDK。Windows 与 macOS 共用 Avalonia 主线；Linux 不在本次正式交付矩阵内。

```sh
dotnet restore BadmintonDraw.sln --locked-mode
dotnet run --project src/BadmintonDraw.Desktop
```

构建、测试、依赖漏洞审计和本地打包见 [构建说明](docs/build.md)。算法与审计边界见 [算法说明](docs/algorithm.md)、[公平性说明](docs/fairness.md)及[规则对应关系](docs/rules-compliance.md)。历史验收文档保留对应版本的事实，不应当作 5.0 的当前通过证明。
