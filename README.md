# 深大羽协羽毛球赛事工作台

面向 Windows 和 macOS 的校园羽毛球赛事工作台，覆盖名单核对、公开抽签、全赛事统一排程、现场材料、赛果导入和备份恢复。

> 当前分支是 **5.0.0 开发候选**，尚未正式发布。赛事助手式 GUI 已完成本地构建、1,105 项全量回归测试及 macOS 代表页面原生检查，详见[本轮 GUI 验证报告](docs/acceptance/v5-gui-2026-10-03.md)。本轮未推送、未运行远端 CI，也未完成 Windows 真机验收或正式 Release。[核心候选历史证据](docs/acceptance/v5.0.0.md)仍绑定原提交；完整状态见[文档中心](docs/index.md)。

## 5.0 解决什么问题

5.0 不再要求用户先为每个项目建立独立存档、分别排程，再合并结果。现在的决策顺序与实际办赛一致：

```text
选择团体赛或单项赛
  → 选择一个或多个项目
  → 选择只做公开抽签或筹备完整赛事
  → 准备名单
  → 公开抽签并确认
  → 统一安排时间、场地和人员容量
  → 导出现场材料并导入赛果
```

- 一场赛事只有一个 `.szbd` 文件，包含全部项目、签表、赛程、赛果和审计。
- 团体赛与单项赛不能放在同一赛事中混排。
- 单项赛可从男单、女单、男双、女双、混双中选择一至五项。
- 名单导入不会自动抽签；抽签不会自动确认、排程或导出现场材料。
- 公开抽签可以作为一次独立工作完成并导出，以后再继续赛事筹备。
- 单项目和多项目共用同一调度器；多项目共享日期、场地、裁判容量、最小休息和每日上限。
- 赛程编辑先查看调整方案，赛果更正先检查记录表，备份恢复先检查备份与恢复范围；保存和材料覆盖需要明确确认，并保留审计记录。

## 开始使用

### 普通使用者

1. 从[5.0 使用说明](docs/usage.md)了解完整流程。
2. 使用 [`samples/v5`](samples/v5/) 中的虚拟名单练习，不要先拿唯一的真实赛事文件试操作。
3. 打印或对外发送材料前，核对抽签状态、赛程范围、文件清单和实际页面效果。
4. 遇到打不开、部分保存、导出残缺或赛果冲突时，先看[故障处理](docs/troubleshooting.md)。

界面按“比赛概览 → 准备名单 → 公开抽签 → 安排赛程 → 比赛现场 → 完成与归档”六步组织。首页可创建新比赛或继续已有比赛；赛程板位于安排赛程步骤内，比赛现场默认先准备材料，再导入结果、查看进展。常用设置直接显示，高级设置和技术记录按需展开，抽签、导入、覆盖和恢复仍须分别确认。

首页与新建页面会隐藏先前比赛的标题、导航和文件路径；从最近列表移除条目不会删除赛事文件。“完成与归档”可以留存当前进度，创建备份不会把尚未结束的比赛标记为完成。设计依据见[赛事助手式 GUI 设计](docs/superpowers/specs/2026-09-20-v5-beginner-friendly-gui-design.md)。

### 本地开发运行

需要仓库 `global.json` 指定的 .NET 10 SDK：

```sh
dotnet restore BadmintonDraw.sln --locked-mode -p:Configuration=Release
dotnet build BadmintonDraw.sln -c Release --no-restore
dotnet run --project src/BadmintonDraw.Desktop -c Release --no-build
```

完整测试、依赖漏洞审计、端到端验收和平台打包见[构建说明](docs/build.md)。Windows 与 macOS 是 5.0 交付目标；Linux 未进入正式验收矩阵。

## 文件和数据安全

| 文件 | 用途 |
| --- | --- |
| `.szbd` | 整场赛事的可信状态；不要直接编辑 SQLite。 |
| 名单 `.xlsx` | 报名输入；学号用于跨项目识别，双打需分别填写两位选手。 |
| 记录表 `.xlsx` | 现场填写和赛果导入；不要删除隐藏标识、公式和来源信息。 |
| 其他 `.xlsx`、`.pdf`、`.png`、`.jpg` | 公示、打印和交接材料，不是另一个赛事状态来源。 |

5.0 工作区 schema 为 500，不读取或迁移 4.x 存档。旧赛事应继续使用对应旧版本打开；试用 5.0 时从名单创建新赛事，不要覆盖唯一旧文件。

工作区保存使用候选副本、事务校验、备份和替换。材料包中的多个文件与工作区审计不是一个跨文件事务：部分文件存在不代表整包完成。遇到错误时保留提示中的候选、备份和暂存路径，按[故障处理](docs/troubleshooting.md)核对状态。

## 导出和现场执行

公开抽签页底只有“导出抽签结果…”一个导出入口，范围、Excel / A4 PDF / PNG / JPEG / 全部格式及 PDF 分页统一在设置窗口中选择。多项目全部确认时，默认导出全部项目；否则默认当前项目。只有全部项目都已抽签且确认状态一致，才能选择全部项目。

已抽签但未确认也可导出，材料标明“抽签结果（待确认）”，文件名带“待确认抽签结果”，导出不会自动确认。选择导出文件夹后，若有同名文件，须逐次确认本次列出的具体替换文件；取消设置不会导出、保存存档或改变上次设置。完整赛事全部确认后可直接继续安排比赛时间，无须先导出。

现场材料包可包含：

- 带时间、场地的项目对阵表；
- 项目记录表、每日赛程和合并记录表；
- 单项计分 PDF 或团体计分 Excel；
- 全赛事质量报告、说明和带 SHA-256 的文件清单。

复杂淘汰图增加 PDF 拼页可以放大，但可能切开连接线或单元格；宽记录表也可能不适合手写。正式赛事必须在目标电脑和打印机上打印预览。质量报告和调度器只检查已经建模的条件，不能替代裁判长确认场馆、人员和赛事规程。

## 代码结构

- `BadmintonDraw.Core`：领域模型、抽签、比赛关系图、调度和硬约束。
- `BadmintonDraw.Persistence`：SQLite 工作区、版本、备份与恢复。
- `BadmintonDraw.Excel`：名单/记录表、Excel/PDF/图片材料。
- `BadmintonDraw.Workflows`：应用用例入口，协调校验、存储、导入、导出和审计。
- `BadmintonDraw.Desktop`：Avalonia 桌面界面。
- `tests`：核心、存储、工作流、故障及桌面生命周期测试。
- `tools/BadmintonDraw.Acceptance`：有界端到端验收和证据产物。

模块责任、保存协议和数据流见[系统架构](docs/architecture.md)。
